# Блок 7 — решения по полям нод (разбор 2026-06-24)

Источник: ревью таблицы редактируемости полей в визуальном компаньоне (Арслан).
Эти решения **переопределяют** раздел «TO BE» Блока 7 из спеки `2026-06-23-meeting-1423-edits-spec.md` и в нескольких местах выходят за его рамки (удаление нод, перенос полей в шаблон, новые контролы).

---

## 0. Сквозное правило (главное)

- **Убрать все поля типа `ai` как прямой выбор.** Везде, где поле редактируемо, — **выпадающий список (Select)**.
- **Последний пункт любого Select — «Сформировать с помощью ИИ».** По нажатию тег поля улетает в промпт-бар (механика `pushChip` сохраняется — не ломаем).
- Следствие для модели: в `NODE_FIELD_EDITABILITY` практически не остаётся чистого `ai`. Вместо него — `select` / `combo` / `template`, у каждого последним пунктом ИИ.

---

## 1. Каналы — схлопнуть поля-компоненты в «Шаблон»

Общий принцип из пометок: на ноде канала остаётся **выбор именованного «Шаблона»**, который несёт все компоненты сообщения. Отдельные поля (тема, отправитель, ссылка, alpha-name, голос, deeplink) **уходят внутрь редактора шаблона** → прямая связь с **Блоком 10** (состав шаблона расширяется).

| Канал | Поле | Решение |
|---|---|---|
| SMS | Шаблон `text` | оставить (Select именованных шаблонов + ИИ-пункт) |
| SMS | Alpha-name `alphaName` | **вынести в шаблон SMS** |
| SMS | Время `scheduledAt` | **таймпикер** — выбор именно времени отправки (не Select) |
| SMS | Ссылка `link` | **удалить** |
| Email | Тема `subject` | **убрать в шаблон** |
| Email | Шаблон `body` | оставить (Select шаблонов + ИИ-пункт) |
| Email | Отправитель `sender` | **убрать в шаблон** |
| Email | Ссылка `link` | **убрать в шаблон** |
| Push | Шаблон `body` | оставить (Select шаблонов + ИИ-пункт) |
| Push | Deeplink `deeplink` | **убрать в шаблон** |
| IVR | Сценарий `scenario` | это **текст для проговаривания** → выбор текста (Select текстов/шаблон + ИИ-пункт) |
| IVR | Голос `voiceType` | **убрать в шаблон** |

**Итог по нодам каналов:**
- **SMS** = «Шаблон» (Select) + «Время» (таймпикер).
- **Email** = «Шаблон» (Select) — тема/отправитель/ссылка теперь внутри шаблона.
- **Push** = «Шаблон» (Select).
- **IVR** = «Сценарий»/«Текст» (Select текстов) — голос внутри шаблона.

## 2. Сигнал и Скоринг

- **Скоринг — отдельная нода** (подтверждает Блок 8). Интересы/триггеры живут в ней, правятся через боковой дровер.
- Сигнал (`signal`): поля `Файл / Сигналов / Сегменты` — комментариев не было → оставляем `readonly` (показ загруженных файлов разворачивает Блок 8).

---

## 3. Логика и поток

- **Ожидание `wait`:**
  - `Режим` → **Select**: «длительность» | «событие».
  - `Длительность` → **композитный контрол**: ввод числа + Select единиц (часы / дни / недели).
  - `Событие` → **Select из справочника событий** (см. §5).
- **Условие `condition`:**
  - `Триггер` → **заменить на «Событие»**, брать из **справочника событий** (новый общий справочник).
- **Сплит `split` (`По` / `Ветки`):** структурные Select (критерий деления и число веток). Остаются **без** пункта «Сформировать с ИИ» — ИИ ветвление не задаёт.

---

## 4. Исходы и конверсия

- **Успех `success` · Цель `goal`** — Select (combo-пресеты) + ИИ-пункт. (Комментария не было → дефолт.)
- **Завершение `end` · Причина `reason`** — Select (combo-пресеты) + ИИ-пункт. (Дефолт.)
- **Витрина `storefront`** — **убрать ноду полностью.**
- **Лендинг `landing`** — **убрать ноду полностью.**

---

## 5. Новые контролы и справочники (следствия)

1. **Таймпикер времени отправки** — для SMS «Время» (возможно, переиспользуемый для других каналов в будущем).
2. **Композитный контрол длительности** — число + единицы (часы/дни/недели) для `wait`.
3. **Справочник событий** (events directory) — новый общий список, питает `wait`.«Событие» и `condition`.«Событие».
4. **Пункт «Сформировать с помощью ИИ»** — добавляется последним в каждый Select; вызывает существующий `pushChip`.
5. **Стартовые тексты шаблонов** — осиротевшие пресеты `smsText / pushTitle / pushText` использовать как стартовые тексты при создании нового шаблона соответствующего канала (не удалять).
