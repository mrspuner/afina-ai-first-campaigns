## 1. Таксономия запросов и сегодняшние mock-обработчики

Пользователь вводит текст в PromptBar. Маршрутизатор в `prompt-composer.tsx` определяет тип ввода и делегирует нужному обработчику. Сегодня все обработчики — regex или жёстко закодированные словари.

### 1.1 Структурные команды графа воркфлоу

**Где:** `src/state/structural-commands.ts`, функция `parseStructuralCommands(input)` (строка 239).

Разбирает свободный текст в список `StructuralOp[]` — операций добавления, удаления и замены узлов. Ядро парсера — два словаря:

- `TYPE_LOOKUP` (строка 33) — прямое отображение: «смс» → `sms`, «пуш» → `push`, «задержка» → `wait`, «витрина» → `storefront` и т.д.
- `REF_SYNONYMS` (строка 55) — синонимы для распознавания _ссылок_ на существующие узлы: `sms`/`смс` → `"смс"`, `ivr`/`call`/`звонок` → `"звонок"`, `delay`/`пауза`/`ожидание` → `"задержка"` и т.д.

Результат применяется функцией `applyOps(graph, ops)` (строка 741) — чистой функцией без сайд-эффектов. Это главный кандидат на замену AI в данном спайке.

### 1.2 Правки параметров ноды

**Где:** `src/sections/campaigns/workflow-view.tsx`, функция `deriveParamsPatch(text, currentParams)` (строка 95).

Работает только когда выбрана конкретная нода. Принимает текст команды и текущий `NodeParams`, возвращает `{ paramsPatch?, sublabel? }`. Внутри — итерация по `NODE_ACTIONS` (словарь структурированных паттернов для каждого типа ноды), затем `fallbackParamsPatch` (применяет «разумное» изменение, если паттерн не совпал — чтобы редактирование ноды никогда не было тихим no-op). Sublabel обновляется только для видимых параметров (длительность ожидания, тип сплита, триггер условия) — не для текста сообщений.

### 1.3 Правки триггеров

**Где:** `src/lib/trigger-edit-parser.ts`, функция `parseTriggerCommand(rawInput)`.

Regex-парсер для работы с триггерами в визарде. Распознаёт:
- «добавь d1.ru, d2.ru» → `{ kind: "edit", add: [...], exclude: [] }`
- «исключи d3.ru» → `{ kind: "edit", add: [], exclude: [...] }`
- «убери всё что я добавлял» → `{ kind: "clear-added" }`
- «верни всё что я исключал» → `{ kind: "clear-excluded" }`
- всё остальное → `{ kind: "fallback", message: "AI пока не подключён…" }`

Домены вытягиваются из текста regex-паттерном `DOMAIN_TOKEN_RE`. Второй кандидат на AI-эндпоинт — см. раздел «Следующие кандидаты».

### 1.4 Статистические запросы

**Где:** `src/lib/stats-query-matcher.ts`, функция `matchStatsQuery(rawText)`.

Сопоставляет ввод с 10 заранее описанными `StatsQueryId` (топ кампаний по доходу, сравнение каналов, тренд по периоду и т.д.). Алгоритм: нормализация + проверка групп альтернатив (каждая группа должна содержать хотя бы одно совпадение). Порядок определений важен: составные запросы (`top-campaigns-income-june`) предшествуют общим (`top-campaigns-income`). Возвращает `StatsQueryMatch | null`.

### 1.5 Информационные вопросы

**Где:** `src/lib/informational-replies.ts`, функция `lookupInformationalReply(text)`.

Трёхуровневое сопоставление: точное совпадение → консервативный нечёткий матч (покрытие токенов ≥ 0.6, нет неоднозначности) → `null`. Каталог `ENTRIES` — ~40 записей, охватывает вопросы о кампаниях, сигналах, визарде (шаги 1–8), настройках. При совпадении возвращает случайный вариант ответа из `replies[]` (несколько вариантов на одну запись — для борьбы с однообразием). `null` означает «не распознано» — вызывающий показывает тёплый fallback.

## 2. Контракт: AI заменяет парсеры, не аппликаторы

**Ключевая идея спайка:** LLM возвращает те же типизированные структуры, которые сегодня выдаёт regex. Аппликаторы — `applyOps`, обработчик `workflow_structural_commands_submit`, dispatch-пайплайн, анимации цикла — не меняются ни на строчку.

### Контракт для структурных команд (первый эндпоинт)

Эндпоинт принимает:

```ts
{ text: string; nodes: Array<{ id: string; label: string; nodeType: string }> }
```

Возвращает:

```ts
{ ops: StructuralOp[] }
```

где `StructuralOp` — тот же тип, что сегодня возвращает `parseStructuralCommands`. Zod-схема (`ai-workflow-schema.ts`) — зеркало этого типа; она же служит гарантом на клиенте при валидации ответа.

### Privacy-граница

На сервер уходит:
- текст команды пользователя
- краткая сводка графа: только типы и подписи узлов, без параметров, без данных аудитории, без ключей

Полный стейт приложения, параметры нод, данные аккаунта — не уходят никогда.

### Ограничение текущего спайка (nodes: [])

`prompt-composer.tsx` не имеет прямого доступа к узлам графа — они живут только в `workflow-view.tsx`. Прокидывать граф через `app-state.ts` или `workflow-view.tsx` — вне скоупа этого спайка (изменение аппликаторов/стейта нарушает контракт «не трогаем существующий пайплайн»).

**Осознанное ограничение:** в текущей реализации на сервер уходит `nodes: []`. Модель работает без контекста текущего графа — она может добавить узел, но не удалить конкретный по ссылке на существующую ноду. Для команд «добавь пуш после email» это достаточно; для «удали третий узел» — нет. Расширение (передача сводки графа из компоузера) — отдельная задача.

## 3. Fallback-цепочка

```
Пользователь отправил команду
    │
    ▼
isAiParserEnabled()? ──── нет ──→ parseStructuralCommands → ops → dispatch
    │
   да
    │
    ▼
fetchAiStructuralOps(text, nodes: [])
    │
    ├── ошибка сети / таймаут 4с / HTTP 5xx ──→ regex → ops → dispatch
    ├── HTTP 429 (квота free tier) ────────────→ regex → ops → dispatch
    ├── ops пустой список ──────────────────────→ regex → ops → dispatch
    │
    └── ops непустой ────────────────────────────→ dispatch напрямую
                                                   (regex не вызывается)
    │
    ▼
regex тоже пустой → текущий путь «Команда не распознана»
```

Таймаут AbortSignal на клиенте — 4 секунды. Клиент трактует HTTP 429 и HTTP 5xx одинаково — оба случая уходят в fallback.

### Оговорки free tier

Google AI Studio (бесплатный тариф) имеет два практических следствия, которые нужно зафиксировать как архитектурные, а не временные ограничения:

1. **Данные запросов.** Google может использовать тексты запросов для улучшения моделей. Это приемлемо: на сервер уходят только текст команды и типы узлов мокового графа (`nodes: []`). Никаких персональных данных, данных аудитории или бизнес-метрик.

2. **Квоты.** Google периодически пересматривает лимиты free tier (~15 запросов/мин на дату написания). Превышение → HTTP 429. Именно поэтому **regex-fallback — постоянная часть архитектуры**, а не временный костыль до платного тарифа. Даже на платном тарифе fallback остаётся: защита от деградации сервиса, сетевых ошибок и cold-start задержек.

## 4. Latency-UX

**Сегодня:** после отправки команды в воркфлоу запускается цикл «Думаю…» на фиксированные 3–5 секунд (имитация обработки), затем применяются операции.

**С реальным AI:** реальный вызов занимает от ~0.5с до нескольких секунд в зависимости от модели и нагрузки. UX-паттерн:

- Цикл «Думаю…» стартует **сразу** после отправки (без ожидания ответа).
- Минимальная длительность цикла — **1.5 секунды** (ощущение «магии», не мгновенного выполнения).
- Максимальная длительность — до прихода ответа от эндпоинта (но не более таймаута 4с).

Точная реализация управления длительностью цикла — сознательно отложена до разрешения открытых вопросов (раздел 5). Связь с планом 001 (гонки воркфлоу): при включённом AI-флаге сетевые задержки делают гонки применения регулярными — план 001 должен быть выполнен до включения флага на демо.

## 5. Решённое и открытые вопросы

### Решено оператором (2026-06-11)

| Вопрос | Решение |
|--------|---------|
| Провайдер | Gemini Flash через `@ai-sdk/google` |
| Тариф | Бесплатный (Google AI Studio) |
| Доступность | Оператор в Грузии — страна поддерживается, ключ без карты |
| Ключ | `aistudio.google.com → Get API key` |
| Модель | `gemini-2.5-flash` (id взят из типов установленного `@ai-sdk/google`, не из памяти) |
| SDK | `ai@6` (Vercel AI SDK), `generateObject` с zod-схемой |

### Открытые вопросы

**1. Переход за пределы free tier.**
При выходе за лимиты потребуется платный тариф или смена провайдера. Кандидаты: `gpt-4o-mini` (OpenAI), Claude Haiku 4.5 (Anthropic). Нужно решить потолок стоимости на запрос и на месяц до выкатки за пределы dev-флага.

**2. Стриминг reasoning-шагов.**
Сегодня цикл «Думаю…» — анимация без содержания. Стриминг промежуточных рассуждений модели (видимый пользователю) потребует отдельного UX-решения и, возможно, другого эндпоинта (`streamText` вместо `generateObject`). В спайке — вне скоупа.

**3. Выкатка за пределы dev-флага.**
Флаг `afina.dev.aiParser` — localStorage, виден только разработчику. До выкатки на реальных пользователей: разрешить открытые вопросы 1 и 2, выполнить план 001, провести нагрузочный тест на free tier квоты.

### Техдолг

`generateObject` помечен `@deprecated` в `ai@6` — рекомендуется `generateText` с параметром `output`. В спайке используется `generateObject` как есть (API стабилен, deprecation не breaking). Мигрировать при стабилизации интеграции, до выкатки за dev-флаг.
