# Подсказки в PromptBar — справочник

Документ описывает, как устроены подсказки (чипы) под PromptBar в прототипе Afina: как они выбираются, в каких разделах и состояниях появляются, и что происходит после клика.

> Источник истины — код в `src/state/suggestion-registry/` и `src/state/select-prompt-suggestions.ts`. Все строки в документе процитированы из кода как есть (на русском).

---

## 1. Как это работает в целом

Подсказки — это «чистая» (без side-effects) система из двух частей:

1. **Селектор** `selectPromptSuggestions(state, ctx)` — `src/state/select-prompt-suggestions.ts`.
   Смотрит на `AppState` и контекст PromptBar (`PromptBarContext`) и строит **Scope** — «где сейчас пользователь» (раздел / состояние / выбранный узел). Возвращает либо `{ kind: "hidden" }`, либо `{ kind: "items", scope, items }`.

2. **Реестр** `resolveSuggestions(scope)` — `src/state/suggestion-registry/registry.ts`.
   Чистая функция `Scope → SuggestionItem[]`. Роутит Scope в один из resolver'ов (секции / wizard / views / node-context / draft-queue / welcome).

Отрисовка — `src/sections/shell/suggestion-bar.tsx`, кнопка одного чипа — `src/components/ai-elements/suggestion.tsx`. Обработка клика — `handlePickSuggestion` в `src/sections/shell/shell-bottom-bar.tsx:282` (и аналог в `src/sections/shell/chat-panel.tsx` для сайдбара).

### Структура данных

`SuggestionItem` (`src/state/suggestion-registry/types.ts:38`):

```ts
{ id: string; label: string; action: SuggestionAction; variant?: "default" | "brand" }
```

`SuggestionAction` — дискриминированное действие, **5 видов** (`types.ts:31`):

| `kind` | Что делает по клику | Где обрабатывается |
|--------|---------------------|--------------------|
| `ask` | Вставляет текст `prompt` в инпут (курсор, `separator: "smart"`, теги сохраняются). Пользователь редактирует и сам жмёт Enter. → уходит в чат-историю раздела. | `shell-bottom-bar.tsx:285` |
| `submit` | Сразу отправляет `phrase` в `chatSubmit` (используется только в Статистике — `stats-query-matcher`). Очищает инпут и чипы. | `shell-bottom-bar.tsx:292` |
| `dispatch` | Прямой `dispatch(action)` в reducer — мгновенное изменение `AppState` (фильтры, сортировки, старт флоу). | `shell-bottom-bar.tsx:298` |
| `chat-submit` | Передаёт `chip` в `welcomeChat.submitChip` (граф онбординга). | `shell-bottom-bar.tsx:301` |
| `command` | Системная команда. Сейчас одна — `apply-all` (вставляет `APPLY_ALL_COMMAND` в инпут). | `shell-bottom-bar.tsx:304` |

`variant: "brand"` — жёлтый акцентный чип (единственный — «Применить все изменения»).

### Семантика `ask` (главная)

`ask` — основной вид для нефункциональных подсказок (вопросы/намерения). Клик **не** меняет состояние сразу: текст вставляется в инпут, открывается чат-история текущего раздела, появляется user-сообщение, затем assistant-fallback. **Чат-история привязана к разделу и очищается при смене раздела** (коммит `ef3f1d6` — «ask-chip semantics + section-scoped chat»).

### Какой ответ даёт `ask`/`submit`

Реального бэкенда нет. Ответ-заглушка для свободного текста и большинства `ask`/`submit` — `mockReplyForFreeText()` из `src/lib/mock-ai-reply.ts:24`:

> **«Принял, посмотрю и сообщу. (Это прототип — реального ответа не будет.)»**

Pipeline ответа — `submit()` в `src/sections/shell/use-chat-submit.ts:115`. Сообщение добавляется в чат-историю (`chat.append`), затем через ~350 мс приходит ответ ассистента. Спец-обработка до fallback:

- **Статистика** (`isOnStatisticsSection`): `submit`-фразы распознаёт `matchStatsQuery` (`src/lib/stats-query-matcher.ts`) и **реально перестраивает таблицу/график** — `runStatsQuery` (см. раздел 4). Нераспознанные фразы уходят в общий fallback.
- **Сигнал-секция, тег триггера:** если в сегменте есть `trigger`-тег и команда парсится (`parseTriggerCommand`), правка применяется к триггеру (`applyToTrigger`) с ответом из `mockReplyFor(parsed)`.
- Демо-фразы `«лёгкий запрос»` / `«сложный запрос»` запускают remix интересов / многошаговую анимацию «думания».

## 2. Приоритет выбора (что показывается первым)

Из `selectPromptSuggestions` (`select-prompt-suggestions.ts:131`). Первое сработавшее правило выигрывает:

1. **Печатает после тега** (`activeTag && hasTypedText`) → `hidden` (подсказки прячутся).
2. **Активный тег** (узел выбран, не печатает) → `node-context` (подсказки по узлу/параметру). Если тег не node-payload → `hidden`.
3. **Непустая очередь черновиков** (`queueLength > 0`) → `draft-queue` («Применить все изменения»).
4. **По View** (`state.view.kind`):
   - `welcome` → `welcome-wave` (чипы из графа онбординга; если их нет → `hidden`)
   - `survey`, `campaign-payment` → `hidden` (fullscreen, хром скрыт)
   - `guided-signal` → `wizard-step` (по `wizardCurrentStep`)
   - `awaiting-campaign` → 3 чипа
   - `campaign-select` → 3 чипа
   - `workflow` → `campaign-feed` (статус `draft`, либо реальный статус кампании, если `launched`)
   - `campaign` → `campaign-feed` (реальный статус кампании)
   - `section` → по имени раздела (`Кампании` / `Статистика` / `Сигналы` / `Настройки`)
5. **Иначе** → `hidden`.

Если у scope нет ни одного чипа — резолюция тоже `hidden` (`resolved()` в `select-prompt-suggestions.ts:60`).

### 3.2 Статистика (`resolveStatistics`, sections.ts:137)

Все чипы — `submit` (распознаются `stats-query-matcher`). Максимум 3 чипа: 1 сравнение периода + 2 разбивки.

**Сравнение периода** (зависит от `state.stats.period.preset`):

| Период | Чип | phrase |
|--------|-----|--------|
| `today` | Сравни со вчера | «сравни с вчера» |
| `this-month` / `last-month` | Сравни с прошлым месяцем | «сравни с прошлым месяцем» |
| `this-quarter` / `last-quarter` | Сравни с прошлым кварталом | «сравни с прошлым кварталом» |
| `this-year` / `last-year` | Сравни с прошлым годом | «сравни с прошлым годом» |
| прочее | Сравни с предыдущим периодом | «сравни с предыдущим периодом» |

**Разбивка по оси** (зависит от `state.stats.rows`):

| `rowKind` | Чипы (label → phrase) |
|-----------|------------------------|
| `campaigns` | Разбей по каналам → «разбей по каналам»; Топ-10 по доходу → «топ-10 кампаний по доходу» |
| `channels` | Разбей по кампаниям → «разбей по кампаниям»; Разбей по креативам → «разбей по креативам» |
| `triggers` / `landings` / `creatives` | Разбей по кампаниям → «разбей по кампаниям»; Топ по конверсии → «топ-10 по конверсии» |
| `days` / `weekdays` / `weeks` / `months` | Лучший день → «найди лучший день по доходу»; Покажи тренд → «покажи тренд за период» |
| прочее (default) | Разбей по кампаниям → «разбей по кампаниям»; Сравни каналы → «сравни эффективность каналов» |

**Что происходит при клике** (`runStatsQuery`, `use-chat-submit.ts:72`): только распознанные `matchStatsQuery` фразы реально меняют UI. Известные сценарии:

| Запрос (id) | Эффект | Ответ ассистента |
|-------------|--------|------------------|
| `group-by-campaigns` | `dispatch stats_set_rows: "campaigns"` | «Перегруппировал по кампаниям.» |
| `top-campaigns-income-june` | `stats_apply_patch` (rows=campaigns, sort income desc, период июнь, rowCount 10) | «Топ-10 кампаний по доходу за июнь.» |
| `compare-channels` | многошаговая анимация «думания» (`playComplexThinking`) | финальный ответ из `complex-thinking-demo` |

Нераспознанные фразы → общий fallback `mockReplyForFreeText()`.

### 3.4 Настройки (`resolveSettings`, sections.ts:266)

Всегда 3 чипа (все `ask`):

| Условие | Чип | prompt |
|---------|-----|--------|

## 4. Wizard (Guided Signal)

Файл: `src/state/suggestion-registry/wizard.ts`. Модель: **wizard = только вопросы** — все чипы `ask`, ветви меняют **формулировку** вопроса, а не действие. Показываются на View `guided-signal` по `wizardCurrentStep`.

**Шаг 1 — выбор сценария:**

| Чип | prompt |
|-----|--------|
| В чём разница между категориями? | «В чём разница между категориями сценариев? Кратко по каждой.» |
| Какую мне сейчас выбрать? | «Какую категорию сценария мне стоит выбрать в моей ситуации?» |

**Шаг 2 — интересы и триггеры** (ветвление по `hasInterests` / `hasDomains` из снимка wizard'а):

- *Нет интересов и нет доменов:* С чего начать? · Откуда вы берёте интересы? · Что такое триггер?
- *Есть интересы И домены:* Стоит ли сузить набор? · Можно ли расширить охват? · Этот набор подойдёт?
- *Только интересы:* Зачем триггеры? · Какие домены выбрать? · Можно ли без триггеров?
- *Только домены:* Зачем интересы? · Какие интересы подойдут? · Не пересекаются ли они?

**Шаг 3 — формат файла:** Какие форматы базы? · Какие поля обязательны? · А если базы нет?

**Шаг 4 — объём:** От чего зависит объём? · Можно поставить максимум? · А минимальный?

**Шаг 5 — бюджет:** Как рассчитывается бюджет? · Можно поменьше? · Можно побольше?
*(в новой модели здесь нет dispatch на маскота — вопрос идёт через общий ask-pipeline.)*

**Шаг 6 — имя сигнала** (ветвление по `nameSet`):

- *Имя не задано:* Как назвать сигнал? · Что-нибудь править?
- *Имя задано:* Поменять название? · Что-нибудь править?

**Шаг 7 — запуск:** Когда запускать? · Что будет после запуска? · Смогу ли я остановить?

**Шаг 8 — результаты:** Что дальше? · Когда делать кампанию? · Где смотреть результат?

> Снимок wizard'а (`hasInterests`, `hasDomains`, `signalNameSet`) живёт в локальном state `guided-signal-section`; если он не передан, поля трактуются как `false` (стартовые подсказки на шагах 2 и 6).

## 6. Node-context (правка узла воркфлоу)

Файл: `src/state/suggestion-registry/node-context.ts`. Появляется, когда в инпуте активен тег выбранного узла (правило 2 приоритета). Все чипы — `ask` (правка идёт через чат раздела).

Индексация: `${nodeType}:${paramLabel}` для конкретного параметра, либо `${nodeType}` для whole-node. Логика `resolveNodeContext`:
1. есть `paramLabel` и чипы для него → отдаём их;
2. иначе → whole-node чипы;
3. иначе → **GENERIC** fallback.

**GENERIC fallback:** Сделать короче («сделай текст короче и яснее») · Сменить тон («перепиши в более дружелюбном тоне») · Добавить выгоду («добавь конкретную выгоду для клиента»).

Покрыты узлы: `signal, success, end, split, wait, condition, merge, sms, email, push, ivr, storefront, landing`. Legacy-типы (`default, channel, retarget, result, new`) → GENERIC.

Чипы по типам узлов и параметрам (точные строки из `node-context.ts`):

| Узел | Параметр / whole-node | Чипы (label → prompt) |
|------|------------------------|------------------------|
| **sms** | Текст | Короче → «сделай текст короче, до 1 SMS-сегмента»; Дружелюбнее → «перепиши текст в более тёплом, дружелюбном тоне»; Добавить выгоду → «добавь в текст конкретную выгоду для клиента» |
| sms | Alpha-name | Имя бренда → «поставь alpha-name с названием нашего бренда»; Короткое имя → «сделай alpha-name короче, до 11 символов» |
| sms | Время | Утро буднего дня → «отправлять в 10:00 по будням»; Сразу → «отправлять сразу после входа в сегмент» |
| sms | Ссылка | Короткая ссылка → «поставь сокращённую ссылку с UTM-метками»; На лендинг → «веди ссылку на посадочную страницу акции» |
| sms | *whole-node* | Сделать лаконичнее → «сократи сообщение и убери лишние детали»; Усилить призыв → «усиль призыв к действию в конце сообщения» |
| **email** | Тема | Цепляющая тема → «сделай тему письма цепляющей, до 50 символов»; Без спам-слов → «перепиши тему без слов-триггеров спам-фильтров» |
| email | Текст | Короче → «сократи тело письма, оставь только суть»; Добавить структуру → «разбей текст письма на абзацы с подзаголовками»; Деловой тон → «перепиши письмо в более деловом тоне» |
| email | Отправитель | От имени бренда → «поставь отправителем имя нашего бренда»; Личное имя → «сделай отправителем имя конкретного менеджера» |
| email | Ссылка | С UTM-метками → «добавь UTM-метки в ссылку для трекинга»; На лендинг → «веди ссылку на посадочную страницу акции» |
| email | *whole-node* | Повысить открываемость → «перепиши письмо так, чтобы повысить открываемость»; Сократить целиком → «сократи письмо целиком в полтора раза» |
| **push** | Заголовок | Короче → «сократи заголовок до 30 символов»; С призывом → «перепиши заголовок с явным призывом к действию» |
| push | Текст | Короче → «сделай текст пуш-уведомления компактнее»; С эмодзи → «добавь подходящее эмодзи в начало текста»; Добавить выгоду → «добавь конкретную выгоду для клиента» |
| push | Deeplink | На нужный экран → «веди deeplink на профильный экран приложения»; С UTM-метками → «добавь UTM-метки в deeplink для трекинга» |

## 8. Welcome / онбординг (welcome-wave)

Файл: `src/state/suggestion-registry/welcome-waves.ts`. На View `welcome`. Источник чипов — граф онбординг-чата (`useOnboardingChat`); реестр оборачивает каждый чип графа в `SuggestionItem` с `action.kind = "chat-submit"`:

```ts
{ id: `welcome-${chip.id}`, label: chip.label, action: { kind: "chat-submit", chip } }
```

Клик → `welcomeChat.submitChip(chip)` — управление возвращается графу онбординга. Если волна пустая → `hidden`.

---

## 9. Где скрываются подсказки

`hidden` (ничего не показывается), когда:

- пользователь печатает после активного тега;
- активный тег — не node-payload;
- View — `survey` или `campaign-payment` (fullscreen, хром скрыт);
- View `welcome` без чипов волны;
- scope разрешился в пустой массив чипов;
- ни одно правило не сработало.
