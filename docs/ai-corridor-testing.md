# Памятка фасилитатору коридорного теста

Коридорный тест — короткая неформальная сессия (15–30 минут), где реальный пользователь работает с прототипом, а фасилитатор наблюдает молча. Цель: поймать живые формулировки и паттерны поведения, которые нельзя придумать самостоятельно.

---

## До сессии

1. **Открыть дев-панель.** Хоткей: `Ctrl+Shift+E` (или `Cmd+Shift+E` на Mac). Панель появляется поверх интерфейса.

2. **Включить «Журнал AI».** Найти переключатель «Журнал AI» в дев-панели, включить. Журнал начнёт записывать каждый AI-обмен в localStorage браузера.

3. **Проверить строку статуса ключа.** В дев-панели должно быть «AI: ✓ (ключ есть)» или аналогичный индикатор. Если показывает недоступность — ключ `GOOGLE_GENERATIVE_AI_API_KEY` не задан или квота исчерпана; AI-функции будут идти через офлайн-фоллбек. В таком случае полезность коридорного теста для AI-сценариев снижается.

4. **Очистить журнал** от предыдущих сессий: кнопка «Очистить журнал» в дев-панели.

5. **Выбрать пресет данных.** Для реалистичных данных — «Полный» пресет (кампании, сигналы, статистика заполнены).

---

## Во время сессии

- **Молчать.** Не подсказывать формулировки, не комментировать действия пользователя. Задача — получить «сырые» формулировки, которые пользователь выбирает сам.
- **Наблюдать.** Отмечать момент, когда пользователь задаёт вопрос в промпт-баре и что происходит в ответ: ответ AI виден в чате.
- **Не объяснять механику AI.** Пользователь должен открывать интерфейс сам, без предварительного брифинга об AI-возможностях.
- **Если пользователь застрял** и явно не понимает как двигаться дальше — минимальный намёк без раскрытия AI-механики: «попробуй написать что ты хочешь сделать».

---

## После сессии

1. **Выгрузить журнал.** В дев-панели: кнопка «Выгрузить журнал» → скачивается JSON-файл с записями AI-обменов.

2. **Очистить журнал** кнопкой «Очистить» — чтобы следующая сессия не смешивалась.

3. **Передать JSON-файл** разработчику или положить в общую папку артефактов.

### Как превратить журнал в кейсы экзамена

Открыть JSON — каждая запись имеет поля:

```json
{
  "at": "2026-06-11T14:23:00.000Z",
  "text": "убери задержку",
  "resultKinds": ["workflow-ops"],
  "outcome": "applied"
}
```

Кандидаты на новые кейсы:

- `outcome: "fallback"` — AI не справился. Если запрос должен был пройти — высокоприоритетный кейс.
- `outcome: "applied"` при подозрительном поведении (пользователь запутался после ответа AI) — проверить, правильное ли поведение зафиксировать.
- Повторяющиеся формулировки — несколько пользователей пишут похожим образом.

Подробнее о формате кейса и как его добавить — см. [`evals/README.md`](../evals/README.md).

## Приватность

- **Журнал живёт только в localStorage браузера тестовой машины.** Он не отправляется на сервер и не уходит за пределы браузера без явного действия «Выгрузить».
- **По умолчанию журнал выключен.** Включается только вручную в дев-панели — на период тестовой сессии.
- **Сервер тексты не логирует.** `POST /api/ai/assist` не пишет ни тексты запросов, ни тексты ответов в логи. При ошибке логируется только тип (`"rate-limited"` / `"ai-failed"`).
- **Перед передачей JSON** убедиться, что в нём нет персональных данных пользователя. Если тест проходил реальный клиент (не внутренний сотрудник) — анонимизировать поле `text` перед передачей.
