# Spec — UI-панч-лист по шаблонам, чату и бюджету (из очереди aim)

**Дата:** 2026-07-13
**Источник:** очередь aim `docs/edits/2026-07-13-aim.md` (14 правок; #1 — тестовая область, пропущена)
**Статус:** согласовано в брейншторме, ждёт ревью перед планом реализации.

## Контекст

Порция точечных UI-правок по прототипу Афины (campaign-centric). Тема пачки — унификация карточек-артефактов, чистка потока создания шаблона в чат-дровере, и мелкая полировка бюджета/визарда. Плюс одна выросшая из правки мини-фича: инлайн-редактирование шаблонов с блокировкой по использованию и дублированием.

Дизайн-инварианты (PRODUCT.md), которые правки обязаны соблюдать:
- Жёлтый `#FFEC00` — редкий сигнал, **не** для подсветок/фокуса полей.
- Тёплая тьма, плотность как у Linear, кириллица first-class, левое выравнивание.

## A. Карточки шаблонов и сигналов

### Карточка шаблона — `src/sections/artifacts/template-card.tsx`

Итоговая раскладка (сверху вниз):
1. **Имя** + карандаш переименования (карандаш `opacity-0`, `group-hover/card:opacity-100`; клик по карандашу — `stopPropagation`).
2. **Поля канала** (`FieldList`):
   - email: строки **Тема** (`subject`) и **Текст** (`body`). Раньше письмо рендерилось кнопкой `EmailField` («Письмо: <тема>») — её убираем; письмо идёт через тот же `dl`-формат `label: value`, что sms/push/ivr (**#2**). Превью тела зажимаем по высоте (`line-clamp-2`), чтобы карточка оставалась компактной — это только карточка, не путать с полным текстом в чате (#8).
   - sms/push/ivr — без изменений.
3. **Разделитель** + подвал: цветной чип канала + серый чип «Использовано N раз» (**#6** — переехали сверху вниз).
4. **Меню ⋯** (`MoreHorizontal` dropdown, правый верхний угол, паттерн как в `ArtifactCard`) с пунктом **«Дублировать»** (см. раздел D). Клик по ⋯ — `stopPropagation`.

Карточка целиком (**#4**): `role="button"`, `tabIndex={0}`, `onClick` → открыть дровер шаблона, `onKeyDown` (Enter/Space). Ховер — **`hover:bg-accent`** + `cursor-pointer transition-colors` (эталон — карточка кампании). Убираем прежнюю кнопку `Eye`/«Предпросмотр» и affordance «Письмо».

Удаляемое: компонент `EmailField`, ветка non-email preview-кнопки, импорты `Eye`/`ChevronRight` если больше не нужны.

### Карточка сигнала — `src/sections/artifacts/artifact-card.tsx`

Одна правка: `hover:bg-accent/30` → `hover:bg-accent` (строка className карточки), чтобы ховер совпал с карточкой кампании и шаблона. Больше ничего не трогаем (кнопки Download/⋯ и их `stopPropagation` остаются).

### Эталон (не меняем)

`src/sections/campaigns/campaign-card.tsx` — `cursor-pointer transition-colors hover:bg-accent`, вся карточка `role="button"`.

**Тесты:** `template-card.test.tsx` — обновить (нет кнопки предпросмотра; клик по карточке зовёт open; карандаш скрыт до hover; ⋯-меню с «Дублировать»). `artifact-card.test.tsx` — ховер-класс (если ассертится).

## B. Сообщения ассистента в чате

Все три правки — на одном потоке создания шаблона (`src/sections/shell/use-template-flow.ts`, `src/sections/shell/prompt-composer.tsx`, `src/sections/shell/chat-history-list.tsx`).

### #7 — дубль сообщения-намерения

**Корень:** `answerChannel` (use-template-flow) вручную `append`-ит `INTENT_PROMPT`, и реактивный эффект в `prompt-composer.tsx` (шов блока 5) тоже публикует его при переходе шага в `intent` (`set_template_channel` ставит `step:"intent"`). Итог — два одинаковых сообщения.

**Фикс:** реактивный эффект — единственный источник `INTENT_PROMPT`. Из `answerChannel` убрать ручной `chat.append(INTENT_PROMPT)` (echo канала пользователем и `setTemplateChannel`/`setTemplateQuestion(null)` остаются). Оба пути (полный флоу через `answerChannel` и прямой `openTemplateCreate` из блока 5) сходятся в состояние `create/intent/channel`, которое эффект уже слушает → ровно одно сообщение.

**Тесты:** обновить тест `answerChannel`, который ассертит наличие `INTENT_PROMPT`.

### #11 — «думание» не прячется после ответа

**Корень:** `runSubmitIntent` добавляет pending-пузырёк «Готовлю варианты…» (`pending:true` → рендерится `ThinkingDots`), но **никогда не резолвит его** — на успехе/ошибке `append`-ит **новое** сообщение. Точки зависают над ответом.

**Фикс:** захватить id pending-пузырька и закрыть его через `updatePending` (и на успехе — текстом вариантов, и в `catch` — текстом ошибки). Точки превращаются в сообщение на месте. Контракт `SubmitIntentChat` расширить: `append` возвращает id, добавить `updatePending(id, text)`.

### #8 — форматирование сообщения с вариантами

Переписать `describeVariant` / `buildVariantsMessage`:
- **Вычистить HTML** из значений полей (`<p>`, `<br>`, `<a>` из тела письма) — хелпер `stripHtml`.
- Формат на вариант: **жирный заголовок** `**N. <имя>**` на своей строке, затем `Тема: …` и `Текст: …` отдельными строками. Между вариантами — **пустая строка**. Текст **не обрезаем** (полный).
- **Цвет текста не меняем** — единый цвет обычного сообщения ассистента; структура только через вес (жирный) и переносы.
- **Рендер:** сообщение помечается флагом `format: "markdown"` (новое опциональное поле `ChatMessage`); `MessageRow` рендерит такой ассистентский текст через `Streamdown` (уже используется в блоке размышлений). Флаг ставится только на это сообщение — остальные сообщения рендерятся как сейчас (plain). Жирный даёт `**…**`; никаких цветовых стилей в markdown не добавляем.

Это сообщение — то самое, которым `updatePending` (#11) закрывает пузырёк.

**Тесты:** `use-template-flow` тесты на `buildVariantsMessage` (нет HTML, есть `**`, пустые строки, полный текст); тест на резолв pending-пузырька.

## D. Редактирование шаблона + замок по использованию + дублирование (#3, расширенный)

Правка выросла в мини-фичу. «Использован» = `usedInCampaigns >= 1` (инкрементится в `app-state` на `campaign_launched`).

### Поведение дровера шаблона

Единый дровер для всех каналов (см. «Плумбинг» ниже). Режим зависит от использования:

- **Не использован (`usedInCampaigns === 0`) → редактируемый.** Клик по тексту поля → инпут → правка **сохраняется в шаблон автоматически** на commit (blur/Enter). Каналы: **письмо, SMS, push**. Низ: «Готово». Подсказка «Изменения сохраняются автоматически».
- **Использован (`≥ 1`) → замок.** Всё read-only. Баннер-объяснение: «Шаблон использован в N кампаниях, поэтому его нельзя редактировать. Продублируйте — копия откроется черновиком, и её можно будет менять.» **Кнопки «Дублировать» в дровере нет** — дублирование живёт в меню ⋯ карточки. Низ: «Закрыть».
- **IVR** — всегда только просмотр (инлайн-правку сценария в эту пачку не берём). Дублируется через ⋯, как и остальные.

### Фокус поля — нейтральный (не жёлтый)

`EditableText` в `email-renderer.tsx` сейчас в режиме правки даёт жёлтый glow `boxShadow: 0 0 0 3px rgba(255,236,0,0.25)` — **убрать**. Заменить на нейтральный фокус: тонкая серая рамка + мягкий серый ring (напр. `0 0 0 1px #b7b7b0, 0 0 0 3px rgba(120,120,120,0.18)`), белый фон инпута. Тот же нейтральный стиль — в новых редактируемых полях SMS/push.

### Редактируемые рендереры SMS/push

`sms-renderer.tsx` и `push-renderer.tsx` сейчас только показ. Добавить инлайн-редактирование их полей по образцу `EditableText` из `email-renderer.tsx` (клик → инпут → commit), с `readOnly`-гейтом и нейтральным фокусом. `EmailRenderer` уже умеет — ему передаём `readOnly` по использованию и `onChange` → автосейв.

### Автосохранение

Новый экшен app-state **`template_content_updated`** `{ id, patch: Partial<NodeParams> }` — пишет content в `MessageTemplate` по id. `onChange` рендерера диспатчит его на каждый commit поля.

### Дублирование

Пункт ⋯-меню карточки **«Дублировать»** → новый экшен **`template_duplicated`** `{ id }`:
- клонирует шаблон: новый id, `name = "<name> (копия)"`, `usedInCampaigns = 0`, тот же `content`;
- добавляет в `templates`;
- открывает копию в дровере **в редактируемом режиме** (она не использована).

### Плумбинг дровера (целевое улучшение)

Сейчас превью шаблона раздвоено: письмо открывается через `EmailEditorPanel` (`openEmailEditor(preview:true)`), а sms/push/ivr — через `TemplatePreviewDrawer`. Для этой фичи **сводим открытие шаблона (все каналы) в один дровер** — расширяем `TemplatePreviewDrawer`: пер-канальные редактируемые рендереры, `readOnly`-гейт по `usedInCampaigns`, баннер при замке, автосейв через `template_content_updated`. Письмо в контексте шаблона идёт сюда. `EmailEditorPanel` остаётся для редактора письма **ноды кампании** (там есть `nodeId`, своя логика применения к графу) — его не трогаем.

**Тесты:** новые для `template_content_updated` и `template_duplicated` (app-state reducer); дровер — редактируемость по `usedInCampaigns`, баннер при замке, автосейв; ⋯-меню карточки → duplicate.

## E. Бюджет — `src/sections/campaigns/budget-breakdown.tsx`

### #13 — стрелка «Коммуникации»

Сейчас: `ChevronRight` (→) в закрытом, `rotate-90` (↓) в открытом. Нужно: **закрыто ▼ (вниз), открыто ▲ (вверх)**. Заменить на `ChevronDown`: без поворота в закрытом, `rotate-180` в открытом (`expanded && "rotate-180"`).

### #14 — пояснение над таблицей

Внутри развёрнутого блока, **перед** `<table>`, добавить приглушённый текст (маленький, `text-muted-foreground` / `text-[#8f8f86]` в тон таблицы, line-height ~1.5):

> Первичные — первое касание по каждому получателю. Повторные — дополнительное касание тем, кто не отреагировал: обычно это заметно повышает отклик, их можно будет отключать при настройке кампании.

**Тесты:** `budget-breakdown.test.tsx` — стрелка (класс поворота по состоянию), наличие пояснения в развёрнутом виде.

## Новые экшены app-state

- `template_content_updated` `{ id: string; patch: Partial<NodeParams> }` — автосейв правок контента шаблона.
- `template_duplicated` `{ id: string }` — клон шаблона (usedInCampaigns=0, имя «… (копия)»), затем открыть в редактируемом дровере.
- `ChatMessage.format?: "markdown"` — опциональный флаг рендера (для #8).

## Вне scope / отложено

- Инлайн-редактирование IVR-сценария.
- Полная унификация `EmailEditorPanel` и `TemplatePreviewDrawer` в один компонент (сводим только точку открытия шаблона; редактор ноды остаётся отдельным).
- «Удалить» в ⋯-меню карточки шаблона (не просили — добавляем только «Дублировать»).
