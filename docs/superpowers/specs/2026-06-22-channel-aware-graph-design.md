# Channel-aware генерация workflow-графа (#6) — Design

**Дата:** 2026-06-22
**Статус:** дизайн утверждён (брейншторм с визуальным компаньоном), готов к написанию плана.
**Источник:** aim batch 3 правка #6; скоупинг — `docs/superpowers/specs/2026-06-22-workflow-ai-backlog.md` §1.
**Заменяет:** ранний черновик плана `docs/superpowers/plans/2026-06-22-channel-aware-workflow-graph.md` (написан до брейншторма, исходил из последовательной цепочки каналов без условия/повтора — устарел, план переписать под этот дизайн).

## Проблема

`createTemplate(signalType, sourceType)` (`src/state/workflow-templates.ts:297`) игнорирует выбранные каналы: берёт фиксированный per-signal-type шаблон из `TEMPLATE_BY_TYPE` (`:254`) и опционально вставляет скоринг (`withScoring`, `:270`). Пользователь выбирает на шаге «Каналы» SMS+IVR, но в графе их нет.

Корневая причина рассинхрона цены: `step-budget.tsx` уже объявляет и передаёт `channels` в `BudgetForecastInput`/`buildBudgetForecast`, но `graphCostFor` молча их теряет — выбор каналов не доходит до `createTemplate`. Это и есть баг aim #6.

## Ключевые решения (итоги брейншторма)

1. **Модель графа = скелет сценария + сгенерированный коммуникационный блок** (не «единый скелет для всех», не «просто подставить каналы»). Каждый из 6 сценариев сохраняет свою обвязку (скоринг / пауза / условие / конверсия / отказ).
2. **Каналы бьют параллельно** — `split → [каналы] → merge` (а не последовательной цепочкой). При **одном** канале — одна нода без split/merge.
3. **Коммуникация — это «юнит с добивкой», а не одиночное касание.** После блока каналов всегда стоит условие «взаимодействовал?». Условие есть даже при одном канале.
4. **Один повтор.** Ветка «НЕТ» (не взаимодействовал) → небольшая задержка → повтор блока каналов → ещё одно условие → ДА: конверсия / НЕТ: «Конец».
5. **Сегментные сценарии** («Апсейл», «Удержание») сохраняют `split по сегментам`; внутри каждой коммуникационной ветки — тот же коммуникационный юнит (с условием и повтором); ветка низшего сегмента → «Конец» без коммуникаций.

## Коммуникационный юнит (переиспользуемая единица)

```
[ split → выбранные каналы → merge ]      (1 канал → одна нода)
   → Условие «взаимодействовал?»
        ├ ДА  → <выход юнита: дальше по сценарию (конверсия → Успех)>
        └ НЕТ → Задержка → [ повтор блока каналов ] → Условие «взаимодействовал?»
                                ├ ДА  → <выход: конверсия → Успех>
                                └ НЕТ → Конец
```

Юнит имеет один вход и один логический «выход для отреагировавших» (обе ветки ДА сходятся в продолжение сценария). Терминал не-отреагировавших — «Конец».

## Размещение юнита по сценариям

- **Линейные** (Регистрация, Первая сделка, Реактивация, Возврат):
  `Сигнал → [Скоринг] → [юнит] → конверсия (Лендинг/Витрина) → Успех`.
  Один юнит в точке основного касания. Существующие вторые касания и фоллбэк-комм-ноды (напр. IVR в NO-ветке «Реактивации», Push после паузы в «Возврате») схлопываются в юнит — их роль теперь выполняет встроенная логика повтора.
- **Сегментные** (Апсейл, Удержание):
  `Сигнал → split(по сегментам)`; каждая комм-несущая ветка = `[юнит]`; низший сегмент → «Конец»; затем `merge → Успех`.

## Архитектура / компоненты

### Новый модуль `channel-nodes.ts`
Единый источник истины «канал → нода». Расположение: рядом с визуалами каналов (`src/sections/campaigns/`) либо `src/state/` — выбрать при планировании, ближе к существующим `defaultParamsFor`/`defaultParams`.

Экспортирует:
- карту `channel → NodeParams`-builder (две вариации, как сейчас: «заполненный» пресет для шаблонов и «пустой» дефолт для ручного добавления), переиспользуя `CHANNEL_LABEL` (`src/sections/campaigns/campaign-cost.ts`) и визуал `getNodeColor`/`NODE_STYLES` (`src/sections/campaigns/node-visuals.ts`);
- `buildChannelBlock(channels)` → `{ nodes, edges }`: при `length > 1` — split→каналы→merge; при `length === 1` — одиночная нода; при `length === 0` — пусто (см. краевые случаи);
- `buildCommUnit(channels, { onEngaged, onExhausted })` → `{ nodes, edges, entryId }`: блок каналов + условие + повтор + второе условие, с подключёнными выходами «отреагировал» и «Конец». Используется и линейными, и сегментными скелетами.

Этот модуль **дедуплицирует** per-channel дефолты, которые сейчас задвоены в `defaultParamsFor` (`structural-commands.ts`) и `defaultParams` (`src/lib/ai/rebuild-schema.ts`): обе точки делегируют свои `sms`/`email`/`push`/`ivr` ветки в новый модуль.

### `createTemplate`
Сигнатура → `createTemplate(signalType, sourceType, channels)`. 6 шаблонов переписываются как **скелеты** с явной точкой вставки коммуникационного юнита (placeholder/маркер), которую `createTemplate` разворачивает через `buildCommUnit`. `withScoring` сохраняется как есть (вставка скоринг-ноды для `new`/`stream`).

### Прокидка `channels`
Третий аргумент протягивается из всех потребителей:
- `workflow-view.tsx` (живой граф канваса — главный потребитель),
- `campaign-graph-cost.ts`,
- `campaign-payment-screen.tsx`,
- `workflow-mini-preview.tsx`.

### Фикс сходимости цены
Починить сигнатуру `graphCostFor` (и связанной `BudgetForecastInput`/`buildBudgetForecast`), чтобы `channels` из `step-budget.tsx` реально доходили до `createTemplate`. После фикса визард и экран оплаты собирают **один и тот же граф** при одинаковых каналах → одинаковая цена.

## Краевые случаи

- **0 каналов:** шаг «Каналы» гарантирует ≥1. На всякий случай — если `channels` пуст/не передан, `createTemplate` падает обратно на легаси-шаблон (текущее поведение), без коммуникационного юнита.
- **1 канал:** блок = одна нода (без split/merge), но условие «взаимодействовал?» и повтор присутствуют.
- **Повтор:** ровно один. Глубина не конфигурируется (решение брейншторма).

## Тестирование

- Генерация юнита: для каждого набора каналов (1, 2, 4 канала) проверить число/типы нод, наличие двух условий, корректность split/merge только при >1 канала.
- Per-scenario: для линейных — юнит в нужной точке + сохранённая конверсия; для сегментных — юнит в каждой комм-ветке + низший сегмент → «Конец».
- **Сходимость цены:** один и тот же набор каналов в визарде и на экране оплаты даёт идентичный граф и идентичную стоимость (регрессионный тест на баг aim #6).
- Дедуп: `defaultParamsFor` и `defaultParams` возвращают те же параметры, что и `channel-nodes.ts` (нет расхождения после слияния).

## Затронутые файлы (карта)

- **Создать:** `channel-nodes.ts` (+ тест).
- **Изменить:** `src/state/workflow-templates.ts` (скелеты + `createTemplate`), `src/state/structural-commands.ts` (`defaultParamsFor` → делегирование), `src/lib/ai/rebuild-schema.ts` (`defaultParams` → делегирование), 4 вызова `createTemplate`, `step-budget.tsx` + `graphCostFor`/forecast (фикс цены).
- **Переиспользовать (не менять логику):** `node-visuals.ts` (`getNodeColor`/`NODE_STYLES`), `campaign-cost.ts` (`CHANNEL_LABEL`).
