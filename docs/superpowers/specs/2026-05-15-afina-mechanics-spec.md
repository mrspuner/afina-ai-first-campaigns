# Спецификация механик прототипа Afina

## Контекст

Прототип Afina (Next.js 16, Tailwind v4, shadcn/ui, motion v12) — AI-first продукт
для B2B-маркетологов. Документ описывает шесть механик, которые нужно внедрить
в существующий прототип, и фиксирует точное поведение каждой — чтобы по нему составить
план реализации и собрать экраны.

Механики связаны: теги в промпт-баре (М5) — фундамент; комментарии (М1) и подсказки
(М6) стоят на нём; домены триггера (М2), статистика (М3) и настройки (М4) — независимы.
Удобный порядок реализации: 5 → 1/6 → 2 → 3 → 4.

Промпт-бар-механики (5, 1, 6) опираются на промпт-бар, который сейчас раскатывается
на все разделы прототипа (см. оговорку в аудите ниже).

## Механика 5 — Теги в промпт-баре

Промпт-бар и теги — это **только AI-путь**: ими пользователь меняет что-то не руками,
а словами. Ручные правки полей в узле применяются напрямую и промпт-бар не задействуют.

### 5.1. Два типа полей в узле

Под «узлом» здесь — любая редактируемая сущность с параметрами: узел воркфлоу, а в демо
это карточки Сигналов и Компаний.

У каждого поля узла своя иконка-маркер типа:

- **Ручное поле — иконка изменения (✎).** Строку нельзя править напрямую. Клик по ✎ →
  клик по строке → строка переходит в режим редактирования → Enter или галочка →
  правка **применяется сразу в узле**. Промпт-бар не участвует.
- **AI-поле — иконка маскота (✦).** Это поля, которые «руками правильно не сделать».
  Клик по параметру → параметр улетает **тегом** в инпут промпт-бара; дальше
  пользователь словами описывает правку.

Иконки ✎/✦ — визуальный маркер типа поля (редактируемое вручную / через AI).

### 5.2. Вид тега

- **Тег параметра:** один пилл = [иконка узла] + имя параметра. Имя узла НЕ пишется —
  иконка узла его обозначает. Пилл окрашен в цвет узла.
- **Тег узла целиком:** клик по самому узлу → один пилл = [иконка узла] + имя узла,
  в цвете узла.
- Цвет берётся тот же, что у узла в workflow (у каждого узла свой цвет). Это позволяет
  читать теги одного узла как группу.

### 5.3. Инпут промпт-бара

Инпут всегда держит **один активный тег + его текст**.

### 5.4. Очередь черновиков

Очередь — парковка непринятых черновиков. Показывается над свёрнутым баром И внутри
раскрытого дровера (один источник данных, два представления).

- Карточка очереди = тег + написанный к нему текст (непринятый черновик).
- Черновик попадает в очередь, когда пользователь **сменил тег в инпуте, не нажав
  Enter** (кликнул другой параметр в этом узле или другой узел) — предыдущий тег
  с текстом паркуется в очередь, новый тег занимает инпут.
- **Клик по карточке** → черновик возвращается в инпут для продолжения правки.
- **✕ на карточке** → выбросить черновик. Откатывать нечего — правка не применялась.

### 5.5. Поведение Enter (зависит от содержимого инпута)

| Что в инпуте | Что делает Enter |
|---|---|
| Свежий тег (только кликнул узел/параметр) | применяет правку **сразу** к узлу |
| Тег, вернувшийся из очереди | кладёт черновик **обратно в очередь**, не применяя |
| Команда «Применить все изменения» | применяет **всю очередь** к workflow, очередь очищается |

### 5.6. «Применить все изменения»

- Пока в очереди есть черновики и в инпуте нет активного тега — под промпт-баром
  показывается подсказка «Применить все изменения». Если активный тег есть,
  показываются его контекстные подсказки (приоритет — М6.1).
- Клик по подсказке → в инпут подставляется команда-текст → пользователь жмёт Enter →
  вся очередь применяется к workflow, очередь очищается.
- Применять выборочно нельзя — только всё разом.

### 5.7. Переиспользование кода

- `PromptChip` / `ChipSegment` — `src/state/prompt-chips-context.tsx`. Модель чипа;
  расширить payload под узел/параметр, добавить цвет узла.
- `ChipEditableInput` — `src/components/ai-elements/chip-editable-input.tsx`. Контейнер
  инпута с чипом.
- `TransientReply` — `src/sections/shell/chat-panel.tsx`. Зона над свёрнутым баром, где
  уже показываются ответы AI; очередь живёт в той же зоне.
- Чип триггера — `src/sections/signals/steps/step-2-interests.tsx`. Существующий приём
  «клик по элементу → чип в бар» обобщается на узлы и параметры.

## Механика 1 — Комментарии на элементах

Комментарии на элементах — это та же **очередь черновиков** из М5. Отдельной системы
комментариев (своя коллекция, поповер-ввод, отдельное «применить») не делаем.

Как это работает:
- Чтобы «прокомментировать» элемент — клик по AI-параметру/узлу (✦): тег летит
  в промпт-бар, пользователь пишет текст.
- «Сохранить комментарий» = сменить тег, не нажав Enter → черновик паркуется в очередь.
- Коллекция комментариев = очередь черновиков (над промпт-баром и в дровере).
- Вернуться и переписать = клик по карточке очереди.
- Применить пачкой = «Применить все изменения».
- На каждый тег — один черновик (на каждый AI-параметр и на узел целиком).

Решения:
- **Маркер на элементе — НЕ делаем.** Узел/параметр не помечается значком о наличии
  черновика.
- **Обратная связь** — очередь видна над промпт-баром: когда черновик паркуется, его
  карточка просто появляется над баром. Этого достаточно — отдельных toast,
  анимаций-полётов, счётчиков на иконке дровера не делаем.
- Механика работает и в разделе «Кампании», и в разделе «Сигналы».
- Дровер при сложных запросах открывается как и раньше; в дровере показывается
  и история AI, и очередь.

## Механика 6 — Подсказки под промпт-баром

Зона под промпт-баром = подсказки. (Зона над баром = очередь черновиков + ответы AI.)

### 6.1. Состояния и приоритет

| Состояние бара | Подсказки |
|---|---|
| Пусто (welcome, нет активного тега, очередь пуста) | общие подсказки, как сейчас на welcome |
| Активный тег в инпуте, текст после тега не печатается | 2-3 контекстные подсказки под тип тега |
| Очередь непустая, активного тега в инпуте нет | «Применить все изменения» |

- Приоритет: если активный тег есть и очередь непустая одновременно — показываются
  **контекстные подсказки активного тега** (активный инпут выигрывает). «Применить все
  изменения» показывается только когда активного тега в инпуте нет.
- Как только пользователь начал печатать текст после тега — **все подсказки
  скрываются**.

### 6.2. Формат и клик

- В чипе подсказки — короткая ёмкая надпись.
- Полный текст (может быть длиннее) — то, что подставляется в инпут.
- Клик: полный текст подставляется в инпут **после тега**, не выполняется
  автоматически. Пользователь видит результат, при желании правит, потом Enter.
- Наведение: обычный hover-стейт чипа, без отдельного превью полного текста — полный
  текст и так появляется в инпуте при клике и редактируем.

### 6.3. Анимация

Появление и скрытие подсказок — плавная анимация (opacity/transform, без резких
скачков). До идеала доводить не нужно — достаточно мягкого перехода.

### 6.4. Каталог подсказок

- На каждый тип тега (тип параметра / тип узла) — 2-3 короткие подсказки + полные
  тексты.
- На первом этапе покрыть типы тегов, входящие в демо: Сигналы, Компании.
- Полный каталог формируется параллельно с каталогом полей.

### 6.5. Переиспользование

- `Suggestion` — `src/components/ai-elements/suggestion.tsx`. Готовый компонент чипа
  подсказки, пока не задействован в промпт-баре.
- Существующие welcome-подсказки — состояние 1 уже работает.

## Механика 2 — Изначальные домены в свёрнутом триггере

Сейчас в свёрнутом триггере видны только пользовательские правки — изначальные
(системные) домены не видны, контекст «что было в триггере» теряется. Нужно показать
системные домены и в свёрнутом виде.

**Архитектурный принцип.** Системные данные неразрушимы — но исключить системный домен
можно. Клик по ✕ на системном домене не удаляет его из системного слоя, а создаёт
обратимое исключение в пользовательском слое. Поэтому ✕ на системных доменах разрешён
и обязателен. Плюса на системных доменах нет: добавление нового домена идёт через
промпт-бар.

### 2.1. Свёрнутый триггер

```
☑ Ипотека — банки                                              ⌄
   vtb.ru · alfabank.ru · gazprombank.ru  +9
   Добавлено: +domrf.ru   Исключено: s̶b̶e̶r̶b̶a̶n̶k̶.̶r̶u̶
```
- Системные домены — превью: показываем столько, сколько влезает в одну строку,
  затем «+N».
- Пользовательский слой — как сейчас: добавленные плюсом/зелёным, исключённые
  красным/перечёркнуто. Это поведение не трогаем.
- Стрелочка-шеврон присутствует (см. 2.3).

### 2.2. Раскрытый триггер

```
☑ Ипотека — банки                                              ⌃
   [vtb.ru ✕] [alfabank.ru ✕] [gazprombank.ru ✕] [s̶b̶e̶r̶b̶a̶n̶k̶.̶r̶u̶ ↩] [+domrf.ru]
   [ + Добавить свой домен ]
```
- Все домены — чипами в одну строку с переносом на следующую, когда строка заполнена.
  «+N» в раскрытом состоянии пропадает — показаны все.
- Каждый системный домен — чип с ✕; клик по ✕ → домен переходит в исключённые
  (перечёркнут). Обратимо — исключённый домен можно вернуть.
- Добавленные пользователем — зелёные чипы.
- В конце — кнопка «Добавить свой домен»: клик → тег «Добавить домен» летит
  в промпт-бар; домен вводится через AI-путь (М5).

### 2.3. Модель клика по карточке триггера

Один клик по телу карточки делает два действия сразу — это сознательно (раздельные
действия на тело карточки оказались неудобны):

- **Клик по чекбоксу** — только выбор триггера.
- **Клик по телу карточки** — выбор триггера + раскрытие/сворачивание одновременно.
- **Клик по стрелочке-шеврону или по «+N»** — только раскрытие/сворачивание, без
  изменения выбора.

Стрелочка-шеврон сохраняется. В свёрнутом состоянии смотрит вниз; клик раскрывает все
домены, «+N» при этом пропадает. В раскрытом состоянии смотрит вверх; клик возвращает
карточку в свёрнутое (стандартное) состояние.

### 2.4. Визуальное разделение слоёв

- Системные домены — обычный стиль чипа. Приглушённый/вторичный цвет НЕ используем.
- Пользовательские правки — цветовой код: добавленные зелёным, исключённые
  красным/перечёркнуто.
- Разделение читается через цвет правок: нейтральное = системное, цветное = твоё.

### 2.5. Переиспользование

- `TriggerCard` — `src/sections/signals/steps/step-2-interests.tsx`. Карточка триггера,
  collapsed/expanded уже есть. Эта часть интерфейса текущей раскаткой промпт-бара
  не затрагивается — аудит для М2 стабилен.
- `TRIGGER_DOMAINS` — `src/data/trigger-domains.ts`. Системные домены.
- `TriggerDelta {added, excluded}` — `src/lib/trigger-edit-parser.ts`. Пользовательский слой.
- `DeltaChip` — `src/sections/signals/steps/step-2-interests.tsx`. Чип правки.
- `parseTriggerCommand` — `src/lib/trigger-edit-parser.ts`. Уже умеет «добавь domain» —
  переиспользуется для тега «Добавить домен».

## Механика 3 — Статистика: убираем дровер, выносим в две кнопки

### 3.1. Что убираем
Старый правый дровер статистики (`statistics-settings-drawer.tsx`, Sheet 640px) убираем
полностью — он конфликтует с AI-дровером (оба претендуют на правую сторону;
многослойный дровер — плохо). Функционал распределяем по двум кнопкам справа сверху
над таблицей.

```
Статистика
┌──────────────────────────────────────────────────────────────────┐
│ Отчёт: Сводный за период ⌄        [⚙ Настройка вида] [⌕ Условия поиска] │
├──────────────────────────────────────────────────────────────────┤
│  таблица отчёта                                                    │
```

### 3.2. Кнопка «Настройка вида»
Открывает попап. Содержит, в частности:
- **Управление столбцами** — отдельный пункт, по клику открывает свой уровень
  настройки: какие столбцы видимые / скрытые (как в Notion), drag-and-drop порядка,
  сортировка.
- **Общие параметры отчёта** — валюта, элемент расчёта, период.
- Прочие визуальные настройки отчёта.
Каждая настройка вида может быть вынесена в отдельное под-меню (см. 3.4).

### 3.3. Кнопка «Условия поиска»
Соседняя кнопка того же вида. Открывает попап с блоком «Условия поиска» — фильтр
по значениям, которые в принципе попадают в таблицу (include/exclude сущностей:
кампании, предложения, абоненты, каналы, креативы, триггеры, сценарии, стратегии).
Это не фильтр строк уже отображённой таблицы. Переиспользуем `search-conditions.tsx`.

### 3.4. Устройство попапов — Notion-стиль drill-in с сохранением
- Оба попапа устроены как вложенное меню Notion (database views): клик по пункту меню
  открывает следующий уровень настройки в той же выпадашке; есть кнопка «назад»
  на предыдущий уровень.
- **Кнопка «Сохранить» — на каждом уровне drill-in.** И на меню 1-го уровня, и на меню
  2-го уровня, и глубже — независимо от того, как далеко зашёл пользователь.
- **Не реактивно.** Таблица на лету не перерисовывается — изменения сложные.
  Изменения применяются и таблица перезагружается по «Сохранить».
- **Защита от потери правок.** Если пользователь пытается закрыть меню с
  несохранёнными изменениями — показывается подтверждающий поповер «Вы уверены, что
  хотите закрыть?» с вариантами подтвердить / отменить.

### 3.5. Шаблоны и название отчёта
Шаблоны отчётов остаются в выпадашке рядом с названием отчёта — уже так
(`report-templates.ts` + template picker Popover). Не меняем.

### 3.6. Переиспользование
- `statistics-view.tsx` — главный экран; в тулбар добавить две кнопки, убрать триггер
  дровера.
- `statistics-settings-drawer.tsx` — содержимое блока «Настройка вида» (`ColumnsList`,
  валюта, элемент расчёта, период) переносим в попап; сам Sheet удаляем.
- `search-conditions.tsx` — блок «Условия поиска» переносим в попап.
- `chip-multiselect.tsx`, `grouped-select.tsx`, `period-field.tsx` — поля переиспользуются.
- Popover (shadcn) — уже используется в статистике (template picker, save dialog) —
  база для попапов и для подтверждающего поповера закрытия.
- `StatisticsFilters` / `statisticsReducer` — `statistics-state.ts`. «Сохранить»
  переносит draft-фильтры в applied и триггерит перезагрузку таблицы.

## Механика 4 — Раздел «Настройки» в личном кабинете

### 4.1. Рамка экрана
- Экран проектируется с нуля. Сейчас в `app-sidebar.tsx` пункты «Настройки»/«Финансы» —
  заглушки без обработчиков; нужен роут/секция.
- **Одна страница, блоки сверху вниз, левое выравнивание** (плотность Linear,
  асимметрия — PRODUCT.md). Не вкладки.
- Нижнего промпт-бара в Настройках **нет**. Полноценного AI-взаимодействия нет — AI
  участвует только в предзаполнении (саммари, интересы) и в секции AI-предложений.
  Поля правятся вручную.
- «Финансы» — отдельная сущность личного кабинета, в этой задаче не трогаем.

### 4.2. Блоки экрана

1. **Сайт компании** — основной URL, ручной ввод (input). «Корневой» источник данных.
2. **Название и направление бизнеса** — название (input) + направление/индустрия
   (select по `DirectionId`). Задаёт вертикаль и набор интересов.
3. **Регионы и география** — где компания работает / куда крутит рекламу. Нужно
   рекламной системе для таргетинга.
4. **AI-саммари о компании** — резюме, которое AI сгенерировал о компании клиента
   (именно о компании, не о сайте). Клиент правит его **полностью вручную** как обычный
   текст и сохраняет. Перегенерации через AI нет.
5. **Интересы** — базовый набор интересов компании на уровне аккаунта (не путать
   с интересами конкретного сигнала).
   - AI предзаполняет набор из сайта.
   - Клиент удаляет лишние интересы крестиком. Свободного добавления вручную нет.
   - Секция «AI-предложения» («Может быть, вам подойдёт») — AI предлагает
     дополнительные интересы; клиент отмечает чекбоксами; отмеченные улетают
     в активные интересы.
6. **Тон голоса бренда** — тон и ключевые сообщения; питает AI-генерацию текстов
   коммуникаций (связь с М5).
7. **Глобальные исключения доменов** — аккаунт-уровневый блок-лист доменов, которые
   никогда не использовать ни в одном триггере. Ручное добавление/удаление.

### 4.3. Каскады

- **Смена URL сайта** — ничего не пересобирается автоматически. Смена URL — просто
  правка поля. Опционально показывается ненавязчивая кнопка «Пересобрать интересы
  и саммари с нового сайта» — решение за пользователем (не затирает ручные правки).
  Существующие сигналы/компании не трогаются.
- **Смена базовых интересов** — не влияет на уже созданные сигналы. Каждый сигнал
  зафиксировал свою копию интересов при создании; новые базовые интересы применяются
  только к новым сигналам.

### 4.4. Связь с сигналами

- При создании нового сигнала интересы берутся по умолчанию из базового набора
  Настроек; затем могут быть переопределены/дополнены под сценарий.
- В UI сигнала можно ненавязчиво обозначить, что набор пришёл из аккаунт-настроек
  по умолчанию и редактируется под сценарий.
- Уже созданные сигналы при изменении базовых интересов не меняются (см. 4.3).

### 4.5. Переиспользование

- `app-sidebar.tsx` — пункты «Настройки»/«Финансы»: повесить обработчик, добавить
  роут/секцию.
- `SectionName` — `src/state/app-state.ts`. Расширить, добавив «Настройки».
- `Survey` — `src/types/survey.ts`. `companyName`, `companyWebsite`, `directionId`
  уже хранятся; Настройки их показывают и редактируют.
- `Interest` / `directions.ts`, `interests-by-direction.ts` — модель интересов
  и маппинг по направлению.
- `InterestChip` — `src/sections/signals/steps/step-2-interests.tsx`. Чип интереса —
  переиспользуется для блока интересов.
- Паттерн доменных чипов из М2 — переиспользуется для «Глобальных исключений доменов».

## Следующие шаги и проверка

Документ — спецификация поведения, не план реализации. Дальше:

1. По спецификации составляется план реализации — удобно по механике на итерацию,
   в порядке 5 → 1/6 → 2 → 3 → 4.
2. Реализация — в отдельном git-воркстри (AGENTS.md), сборка экранов через Figma MCP.
3. Проверка каждой механики в работающем прототипе на `localhost:3000`:
   - **М5:** клик по AI-полю ✦ кидает тег; Enter на свежем теге применяет сразу; смена
     тега без Enter паркует черновик в очередь над баром; «Применить все изменения»
     применяет очередь и очищает её.
   - **М1:** комментарии работают как очередь черновиков; маркеров на элементах нет;
     карточка появляется в очереди над баром.
   - **М6:** подсказки под баром меняются по состоянию (welcome / активный тег /
     непустая очередь), скрываются при начале ввода, плавно анимированы.
   - **М2:** свёрнутый триггер показывает системные домены превью + «+N» и стрелку;
     клик по телу карточки выбирает и раскрывает, по чекбоксу — только выбор,
     по стрелке/«+N» — только раскрытие; раскрытый — чипы с ✕, кнопка «Добавить свой
     домен».
   - **М3:** в статистике нет правого дровера; две кнопки открывают drill-in попапы;
     на каждом уровне есть «Сохранить»; закрытие с несохранёнными правками
     спрашивает подтверждение; «Сохранить» перезагружает таблицу.
   - **М4:** экран «Настройки» — одна страница с блоками; поля правятся вручную; смена
     сайта и базовых интересов не каскадит автоматически.
