# aim — режим «Область» со скриншотом (region snapshot)

**Дата:** 2026-07-06
**Скилл:** `~/.claude/skills/aim/` (глобальный, вне репозитория проекта)
**Статус:** design approved, готов к плану

## Проблема

Сейчас aim умеет только точечный пик: пользователь держит Alt, кликает по **одному**
элементу, пишет комментарий. Когда правка касается **участка экрана** (несколько
элементов, композиция, «вот этот блок целиком»), точечный клик не передаёт границы
намерения — агент не понимает, на какой именно объект/зону показывает пользователь.

## Цель

Добавить режим **выделения прямоугольной области** с приложением **скриншота всего
вьюпорта, на котором выделенная область помечена** (не кроп — весь экран + аннотация
рамкой). Агент читает этот PNG и точно понимает, на какую зону обращено внимание.

Ключевое требование пользователя дословно: *«нужен скрин экрана, с наследованием
выделенной мной областью — чтобы ИИ смог понять на какой объект я обращаю внимание»*.

## Не-цели (YAGNI)

- **Скриншоты не добавляем к точечному Alt-клику** — там fiber точен, скрин мало что
  даёт. Точечный пикер остаётся без изменений. (Лёгкое будущее расширение.)
- **Никаких MCP** для захвата. Кадр снимается клиент-сайд, самодостаточно.
- Не делаем произвольные (не-прямоугольные) выделения, не делаем мульти-область за
  один снимок.
- Не пиксель-QA: цель — понимание зоны, не байт-в-байт рендеринг.

## Решение по механизму захвата (принято)

**Клиент-сайд растеризация вьюпорта** через `snapdom`, с дорисовкой рамки на canvas.

Почему клиент-сайд, а не MCP:
- Кадр 1:1 совпадает с **реальным состоянием** приложения (wizard-state, сид-данные,
  скролл) — отдельный браузер под MCP часто оказался бы на другом экране.
- **Аннотацию (рамку) тривиально запечь** на canvas после растеризации; через MCP
  агенту пришлось бы дорисовывать её самому (нет image-либы).
- Не нужен подключённый MCP, работает и в `queue`, и в `live`.
- Playwright MCP в этом окружении вообще не сконфигурирован (есть только
  `chrome-devtools` и `claude-in-chrome`).

Риск точности приемлем: PRODUCT.md держит glassmorphism/glow в **анти-референсах**, а
именно `backdrop-filter`/blur — главная слабость DOM-растеризаторов. Продукт их
избегает → потеря минимальна.

## Интеракция — режим «Область»

Отдельный режим рядом с текущим Alt-пикером. Два входа с разной семантикой:

| Вход | Семантика |
|---|---|
| Тумблер «Область» в меню чипа | **Залипающий**: армирован, пока не выключишь. Снимай области подряд. |
| **Option + Space** | **Разовый**: армирует на один снимок; после Submit/Esc сам выключается назад в обычный режим. |

Пока режим армирован (любым входом):
- Курсор `crosshair`; тонкое затемнение вьюпорта — сигнал «ты в снайпе области».
- **Drag мышью в любом месте** рисует прямоугольник. **Alt держать не нужно** — это
  отдельный режим, не Alt-жест. На время арма клики по приложению перехватываются
  capture-слоем (host получает `pointer-events`).
- Отпустил → клиент-сайд скрин (вьюпорт + помеченная рамка) → та же панель
  комментария (queue/live тумблер, textarea).
- **Esc** — отмена текущей рамки/панели и разоружение. Повторный Option+Space или клик
  по тумблеру — тоже выход.
- Чип показывает активный режим (лейбл/точка «область»), чтобы было видно, что
  app-клики сейчас перехватываются.

Точечный пикер (**Alt + клик**) не пересекается: когда режим области выключен — всё
как сегодня.

**Нюанс шортката:** `Option+Space` на Mac в текстовых полях вставляет неразрывный
пробел. Ловим шорткат только когда панель закрыта и фокус **не** в input/textarea, с
`preventDefault()`.

### Порядок захвата (важно для корректности)

На `mouseup` (область зафиксирована), до открытия панели:
1. Исключить свой UI из кадра. `#aim-host` — это light-DOM элемент (shadow-root только
   *внутри* него), поэтому при обходе документа snapdom его захватит — исключаем явно
   (опция `exclude`/`filter` snapdom по `#aim-host`, либо временно `display:none` на
   host на время захвата). Арм-затемнение и marquee-рамку тоже временно снимаем.
2. `snapdom` растеризует **вьюпорт** (виден. область документа) → получаем canvas/битмап.
3. На результирующем canvas: затемнить всё **вне** региона (полупрозрачный тёмный
   слой), обвести регион ярким штрихом (цвет активного режима aim — pink/cyan).
4. Даунскейл: если ширина кадра > 1600px, масштабируем до 1600px (лёгкий и читаемый
   PNG; retina-safe — учитываем `devicePixelRatio` при маппинге координат региона в
   пиксели canvas ДО даунскейла).
5. Экспорт PNG (`canvas.toDataURL('image/png')` или `toBlob`) → base64.
6. Открыть панель. Растеризация быстрая (~50–200мс); на это время в панели/чипе можно
   показать краткое «снимаю…».

Обработка ошибок: если canvas «запачкан» cross-origin картинкой и экспорт падает —
событие уходит **без** скрина (`screenshot: null`) + тост «скрин не удался». Правка не
теряется.

## Доставка snapdom

- `snapdom` вендорится в скилл: `~/.claude/skills/aim/scripts/vendor/snapdom.min.js`
  (получить через `npm pack @zumer/snapdom` при реализации; коммитить как часть скилла).
- Хелпер-сервер отдаёт его: `GET /snapdom.js` (по аналогии с `/overlay.js`).
- Оверлей грузит лениво через динамический `import()` при первом использовании области
  (overlay.js — классический IIFE, dynamic import работает). Без CDN → CSP приложения
  не мешает.

## Схема события (расширение)

`server.mjs` уже резервирует поле `screenshot` в `normalizeEvent` (строка 132). Меняем
его так, чтобы сервер **сам** сохранял картинку и клал в событие только путь, а не
base64 (иначе inbox.jsonl раздувается).

Клиент → POST `/click` добавляет:
```jsonc
{
  // ...существующие mode/url/comment...
  "kind": "region",                 // "element" (по умолч.) | "region"
  "region": { "x": 120, "y": 80, "w": 480, "h": 220 },   // CSS px во вьюпорте
  "viewport": { "w": 1440, "h": 900 },
  "fiber": {                        // для региона — не одиночный элемент
    "region": true,
    "ancestor": "ComparisonWizard", // наименьший компонент, целиком содержащий регион
    "components": ["Card", "Button", "PriceRow"]  // уникальные не-примитивы в регионе
  },
  "shotData": "data:image/png;base64,...."   // только при kind=region и успешном захвате
}
```

Сервер:
- Если есть `shotData` — декодирует, пишет `.claude/aim/shots/<id>.png`, ставит
  `event.screenshot = { path: "shots/<id>.png", w, h, region, viewport }`. **base64 в
  inbox.jsonl не пишем.**
- `.claude/aim/` уже целиком в `.gitignore` → `shots/` игнорируется автоматически, менять
  gitignore не нужно.
- Поднять лимит тела запроса с 5MB (строка 77) до ~12MB — крупные вьюпорты.

Итоговое событие в inbox.jsonl / SSE:
```jsonc
{
  "id": "...", "ts": "...", "mode": "queue|live",
  "url": "...", "comment": "...",
  "kind": "region",
  "region": { "x":120,"y":80,"w":480,"h":220 },
  "fiber": { "region": true, "ancestor": "ComparisonWizard", "components": [...] },
  "element": null,
  "screenshot": { "path": "shots/<id>.png", "w": 1440, "h": 900,
                  "region": {...}, "viewport": {...} }
}
```

## Разрешение исходника для области

Оверлей по региону собирает fiber-инфо не одного элемента, а множества:
- Перебрать элементы, пересекающие rect (через `elementsFromPoint` по сетке точек
  внутри региона, либо обход поддерева и проверка `getBoundingClientRect`).
- Для каждого — `findFiberInfo` (уже есть), собрать `userComponent`.
- `components`: уникальные не-примитивные имена.
- `ancestor`: наименьший компонент, чей DOM-элемент **целиком** содержит регион (идём
  от общего DOM-ancestor вверх по fiber до первого не-примитива).

Агент резолвит источник: **скриншот** (визуально, что за зона) + `ancestor`/`components`
(grep-цели: `rg "(function|const) <ancestor>"`) + pathname URL — та же стратегия, что
сегодня, но на область.

## Тестирование

Код инжектится в браузер — юнит-тестами покрывается плохо. План:
- **Node-тест сервера**: POST `/click` с `kind:region` + маленький `shotData` →
  проверить, что `shots/<id>.png` создан, а в inbox.jsonl попал `screenshot.path` (не
  base64). Проверить `GET /snapdom.js` отдаёт вендор-файл.
- **Node-тест to-md**: событие со `screenshot.path` рендерит `![...]` в markdown.
- **Ручной smoke**: boot aim → включить «Область» тумблером → протянуть рамку на реальном
  экране → убедиться, что PNG сохранён с корректной помеченной рамкой, событие содержит
  region+ancestor+components; повторить через Option+Space (разовый) и в live-режиме
  (агент Read'ит PNG). Проверить, что Option+Space в textarea не срабатывает.

## Риски / оговорки

- **Точность растеризации**: `backdrop-filter`/WebGL/некоторые фильтры могут рендериться
  плоско. Приемлемо для «понимания зоны» (продукт glass избегает).
- **Cross-origin `<img>`**: пачкает canvas → экспорт падает. Обрабатываем как мягкую
  ошибку (событие без скрина + тост).
- **DPR-маппинг**: координаты региона (CSS px) → пиксели canvas snapdom с учётом
  `devicePixelRatio` до даунскейла, иначе рамка съедет.
- **Option+Space** может конфликтовать с системными/браузерными хоткеями на не-Mac —
  `preventDefault` + гейт по фокусу; на Mac основной кейс.
- **Размер PNG**: даунскейл до 1600px + запас лимита тела 12MB закрывают retina-вьюпорты.
