## #1 · Фазы, удаление Слияния, Сплиттер → ИИ

### Что реально в коде
- `merge`-ноды: шаблоны **Апсейл** (`workflow-templates.ts:134`) и **Удержание** (`:224`), сегментный сборщик `buildSegmentedChannelTemplate` (`seg_merge`, `:483`), и динамически в `buildChannelBlock` (`channel-nodes.ts:230`) при `channels.length > 1`.
- `buildChannelBlock` возвращает единый `exitId` = merge. Потребитель — `buildCommUnit` (`channel-nodes.ts:361,371`) соединяет `exitId → cond`.
- Ссылки на `merge`: типы (`workflow.ts:14,84,182`), AI-схемы (`rebuild-schema.ts`, `ai-workflow-schema.ts`), визуал (`node-visuals.ts`), валидация (`workflow-validation.ts:24`), рендер (`node-card-content.tsx:82`), `structural-commands.ts:282` (label). Плюс тесты.
- Регистрация «Конец» (`workflow-templates.ts:83`) — **сирота**, ни одно ребро не ведёт в него (граф линейный, некому обрываться).
- Сплиттер A6: `node-field-editability.ts:65-69` — `by`/`branches` = `manual`/`select`. Рендер — не общий цикл, а компонент `SplitFields` (`split-fields.tsx`), т.к. `split` исключён из generic-цикла (`node-card-content.tsx:408`).

### Решения
1. **Удаление Слияния (user-facing «полностью»):** ни один шаблон/сборщик не создаёт `merge`; `merge` убирается из AI-схем (чтобы ИИ не восстанавливал). Тип `merge` в union формально остаётся (полное удаление из TS-типа каскадит в мёртвые ветки визуала/валидации без пользы для критериев приёмки), но **в продукте ноды нет**. Тесты, утверждающие наличие merge, переписываются под прямое схождение.
2. **`buildChannelBlock`:** возвращает `exitIds: string[]` вместо одного `exitId` (много каналов → каждый канал это выход). `buildCommUnit` соединяет каждый `exitId` со следующей нодой напрямую. Схождение стрелок в целевой ноде — ожидаемо.
3. **Шаблоны:** Апсейл, Удержание, сегментный сборщик — переписать так, чтобы ветки шли напрямую в следующую ноду (Успех/Задержка/Условие). Позиции нод выправить слева-направо (фазы источник→коммуникация→результат — это визуальная раскладка, не структура данных).
4. **Орфан «Конец» в Регистрации → удалить** (линейный сценарий без обрыва).
5. **Сплиттер → ИИ:** `node-field-editability.ts` `by`/`branches` → `editability: "ai"`, снять комментарий A6. `SplitFields` — рендер строк с иконкой-ассистентом (mascot) вместо селектов; клик открывает **дровер вопросов Сплиттера**. Дровер — новый content-mode в `ChatState` по образцу `open_scoring_drawer` (панель с вопросами + ввод, применяющий изменение веток через существующий structural-движок). Ветки/пути перешиваются через `applyReplace`/`buildFanOut` адаптированные под без-merge топологию.

### Критерии приёмки (из спеки)
- [ ] Нет `merge` ни в шаблоне, ни в собранном графе.
- [ ] Ветки сходятся стрелками в следующую ноду без промежуточного узла.
- [ ] Клик по «Ветки»/«По» открывает дровер ИИ, не селект.
- [ ] Изменение числа веток через ИИ достраивает/удаляет пути и перешивает рёбра.
- [ ] В Регистрации нет ноды без связей.
- [ ] Все 6 сценариев создаются и проходят валидацию запуска.

## #3 · Экран review в Survey + вход из настроек

### Что реально в коде
- Машина фаз `survey-section.tsx`: `form → awaiting → interests → matching → scenarios` (union `:16-21`).
- `accountSettings` — `src/types/account-settings.ts` (10 полей). Reducer `survey_completed` (`app-state.ts:928-947`) мержит **только 3** поля (`companyWebsite`, `companyName`, `directionId`); остальные 7 — из `DEMO_ACCOUNT_SETTINGS` (initialState). **Спека ошибочно** описывает молчаливое применение 10 полей из парсинга.
- `survey-awaiting.tsx` — чистая анимация, **не** пишет в accountSettings.
- Блоки настроек — **без пропсов**, пишут **живьём** через `settings_updated`. `OnboardingInterestsScreen` — локальный state, ничего не персистит.

### Решения
1. **Новая фаза `review`** между `awaiting` и `matching`, **заменяет `interests`.** Машина: `form → awaiting → review → matching → scenarios`.
2. **Новый `onboarding-review-screen.tsx`** по образцу `onboarding-interests-screen.tsx`, с **локальным staging-состоянием**, засеянным из `accountSettings` (в прототипе = DEMO). Контролы — click-to-edit, 3 группы (Компания / О бизнесе / Коммуникации) по раскладке спеки. Дескрипшенов нет; лейблы только у «Коммуникаций».
3. **Отложенный коммит:** данные в `accountSettings` пишутся **один раз** на «Всё верно, продолжить» — новый экшен `account_review_confirmed` (patch = все проверенные поля), затем `setPhase(matching)`. Это удовлетворяет критерий «данные попадают только после подтверждения» (живые блоки настроек для review не переиспользуем именно из-за живой записи).
4. **Вход из настроек:** в `page.tsx` ветка `view.name === "Настройки"` — если `surveyStatus !== "completed"`, монтируется тот же `SurveySection` (канонический флоу, fullscreen), `onComplete` возвращает в Настройки. Один флоу, без развилок.

### Критерии приёмки
- [ ] После парсинга — экран review со всеми полями до применения.
- [ ] Исключения (домены) видны и удаляемы на review.
- [ ] Регионы — мульти-выбор в отдельной строке.
- [ ] `OnboardingInterestsScreen` в цепочке нет; интересы на review.
- [ ] Данные в accountSettings — только после «Всё верно, продолжить».
- [ ] Оба входа проходят один флоу.
- [ ] Нет дескрипшенов; лейблы только у «Коммуникаций».

## #5 · Онбординг-оверлей: 4 шага + точечная жёлтая подсветка

### Что реально в коде
- `intro-overlay.tsx` — `STEPS` (3, `:115`), без target/spotlight. «Подсветка» = backdrop подъезжает (`isPromptStep`, `:26`, `transition-[bottom]`). Текст `:117` «Знакомьтесь — ИИ афина». Вперёд-только, `StepDots`. Монтаж в `page.tsx` (`welcome && !introSeen`).
- Цели в баре: input `[data-slot="input-group"]` (без ref), подсказки — селектора нет (`suggestion-bar.tsx:42`), иконка панели `[aria-label="Открыть в drawer"]` (`prompt-bar.tsx:94`).
- Жёлтый: `var(--brand)` = `#FFEC00`; утилиты `bg-brand`/`ring-brand`; `--brand-muted` для полупрозрачной заливки.

### Решения
1. **4 шага:** знакомство → промпт (input) → подсказки → боковая панель. `IntroStep` получает `target?: string` (селектор data-атрибута).
2. **Точечная подсветка** вместо «отъезда»: на шагах 1–3 измеряем `getBoundingClientRect` целевого элемента и рисуем spotlight трюком `box-shadow: 0 0 0 9999px rgba(bg,.72)` на позиционированном элементе + жёлтая рамка `ring-brand` / `outline` + мягкое свечение. Реагируем на resize/scroll. Диалог-карточка смещается, чтобы не перекрывать подсвеченный элемент.
3. **Хуки целей:** добавить `data-onboarding="prompt-input|prompt-suggestions|prompt-panel"` на три элемента. Подсказки могут отсутствовать в DOM — обеспечить видимость на онбординге либо мягкий фолбэк.
4. **Нейминг:** правка `:117` → «Знакомьтесь — афина ИИ» (единственный инстанс в рамках #5; глобальный #9 не берём).

### Критерии приёмки
- [ ] 4 шага: знакомство → промпт → подсказки → панель.
- [ ] На каждом промпт-шаге жёлтым подсвечен ровно один элемент бара.
- [ ] Оверлей не «отъезжает» — фокус через просвечивание + жёлтая рамка.
