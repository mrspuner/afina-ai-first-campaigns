# Дизайн: правки экрана review онбординга + пустое состояние настроек (aim, 2026-07-06)

## Контекст

Источник — 11 UI-правок, собранных через aim (`docs/edits/2026-07-06-aim.md`). Десять из
них касаются экрана проверки данных онбординга `OnboardingReviewScreen`
(`src/sections/survey/onboarding-review-screen.tsx`), один (#11) — входа в раздел
«Настройки».

Ключевой сдвиг: экран review сейчас построен на **click-to-edit «типографике»**
(`InlineText`/`InlineParagraph` — значение выглядит как текст, по клику превращается
в контрол). Правки просят обычную **форму с видимыми полями и лейблами** плюс новый
паттерн **«+ Добавить» → выпадашка со справочником** для чипов. Такой же формы
(лейбл-поля) уже есть в разделе «Настройки» (`SettingsBlock`/`SettingsField` +
блоки), но без комбобокса-справочника.

Стадия — UX-прототип (AI по regex). Цель — валидировать UX, не перформанс.

## Цель / объём

Внести все 11 правок:

| # | Область | Что делаем |
|---|---------|-----------|
| 1 | Кнопка «Назад» | `variant="outline"` + текст «Назад» (стиль вторичных кнопок визарда). Не иконка-стрелка. |
| 2 | «Всё верно, продолжить» | `variant="default"` (белая, как основная кнопка визарда). |
| 3 | Чип домена в шапке | **Баг**: наследовать введённый сайт из шага формы, а не DEMO. |
| 4 | Подпись «Афина изучила…» | Убрать `<p>` под заголовком. |
| 5 | Группа «Компания» | Вертикальные лейбл-поля (`Input` + `DirectionCombobox`), вместо инлайн-типографики. |
| 6 | Интересы | Убрать предлагаемые чипы; одна кнопка «Добавить интерес» → комбобокс из библиотеки интересов. |
| 7 | Группа «О бизнесе» | Лейбл-поля + подписи (описание = `Textarea`, интересы = чипы+комбобокс). |
| 8 | Группа «Коммуникации» | Полноценные поля (`Textarea`) с лейблами; исключения = чипы+комбобокс. |
| 9 | «Добавить регион» | Комбобокс из справочника регионов РФ. |
| 10 | Домены-исключения | Кнопка «Добавить» → комбобокс: известные домены как подсказки + любой свой. |
| 11 | Вход в «Настройки» | Первый вход (аккаунт не настроен) → пустой экран-заглушка с подводкой и кнопкой, запускающей опрос (вместо авто-запуска опроса). |

## Не-цели

- Рефактор блоков раздела «Настройки» (кроме добавления `SettingsEmptyState` и ветки роутинга) — вне объёма.
- Реальный AI-fill: механика «афина заполняет» остаётся прототипной (существующий опрос/DEMO).
- Инлайн-AI-заполнение блоков настроек прямо на экране (отклонённый вариант #11-C).

## Архитектурное решение (подход A)

Вынести общие примитивы, review-экран переписать как форму на них с локальным
стейджингом. Отклонены: B (всё inline — дублирование, распухание файла) и C (рефактор
блоков настроек под staged-режим — объём/риск больше задачи).

## Компоненты

### `DirectoryChipsField` (новый, общий)
Файл: `src/sections/survey/directory-chips-field.tsx` (рядом с `DirectionCombobox`,
переиспользуемый).

Строка удаляемых чипов + кнопка-чип «+ Добавить» → `Popover` с `Command`
(поиск + список справочника). Основа — существующий `DirectionCombobox`
(Popover + Command).

Пропсы (контролируемый, без глобального стейта — чтобы работал и в staged-review, и позже в настройках):
- `items: { id: string; label: string }[]` — текущие чипы.
- `directory: { id: string; label: string; hint?: string }[]` — справочник (уже без активных).
- `onAdd(item)` / `onRemove(id)`.
- `allowCustom?: boolean` — разрешить добавить произвольное значение из строки поиска (создаёт `{ id: value, label: value }`).
- `addLabel`, `searchPlaceholder`, `emptyText`, `removeLabel(item)` — тексты.
- опционально `groups` — разбить справочник (напр. «Рекомендованные афиной» сверху).

Поведение: клик по «+ Добавить» открывает popover; выбор пункта → `onAdd`; при
`allowCustom` и вводе, которого нет в справочнике, — пункт «Добавить „{value}“».

### `OnboardingReviewScreen` (переписан)
Файл: `src/sections/survey/onboarding-review-screen.tsx`.

- Принимает `survey: Survey` (новый проп) — для наследования данных (см. #3).
- `draft` сеется из `accountSettings` (DEMO — «что поняла афина»), но `companyWebsite`
  переопределяется из `survey.companyWebsite`, если он непустой (суть бага #3 — сайт).
  `companyName`/`directionId` берутся из `survey` только когда там непустое значение,
  иначе остаются из DEMO (у свежего юзера они в `survey` пусты — не затирать DEMO).
  `aiSummary`/интересы/тон и т.д. — из DEMO (в прототипе AII их не генерит из сайта).
  `survey.taskDescription` в review не маппится (это «задача», а не саммари компании).
- Шапка: чип домена (из `draft.companyWebsite`) + `h1`. **Подпись убрана** (#4).
- Группа «Компания» (#5): лейбл-поля — «Название компании» (`Input`), «Направление»
  (`DirectionCombobox`), «Регионы» (`DirectoryChipsField`, справочник РФ, #9).
- Группа «О бизнесе» (#7): «Описание бизнеса» (`Textarea` с лейблом),
  «Интересы» (`DirectoryChipsField`, справочник интересов, #6).
- Группа «Коммуникации» (#8): «Тон бренда» (`Textarea`), «Ключевые сообщения»
  (`Textarea`), «Исключения (домены)» (`DirectoryChipsField`, домены, #10) — все с лейблами.
- Футер: «Назад» `variant="outline"` (#1) + «Всё верно, продолжить» `variant="default"` (#2).
- Удаляются: `InlineText`, `InlineParagraph`, `ChipEditRow`, `InterestChips`, `DomainChips`.
  Лейбл-поле — локальный примитив `Field({ label, children })` (лейбл + контрол).
- Стейджинг сохраняется: правки в локальный `draft`, коммит `account_review_confirmed`
  по «Продолжить» (как сейчас).

Локальные операции над `draft` для чипов:
- Регионы: `regions` (строка через запятую) ↔ массив, как сейчас; add/remove через `setRegions`.
- Интересы: `onAdd` → `patch({ interests: [...draft.interests, item] })` (+ убрать из `suggestedInterests`, если там был); `onRemove` → в `suggestedInterests` (как сейчас, `moveActiveToSuggestion`).
- Домены: `patch({ domainBlocklist })` add/remove.

Интересы (#6): предлагаемые чипы больше не рисуются отдельно. Справочник комбобокса —
каталог интересов (`getInterestById` по `INTERESTS_BY_DIRECTION[draft.directionId]` в
приоритете, затем прочие), исключая уже активные. AI-предложенные
(`draft.suggestedInterests`) показываются группой «Рекомендованные афиной» сверху в
комбобоксе (ценность AI сохраняется, точка входа — одна кнопка). Контролируемый —
без `allowCustom`.

### `SettingsEmptyState` (новый, #11)
Файл: `src/sections/settings/settings-empty-state.tsx`.

Пустой экран-заглушка: маскот (`/mascot-icon.svg`) + заголовок/подводка (пример:
«Расскажите о вашей кампании — и афина настроит всё под вас», финальный копирайт
уточним при вёрстке) + одна кнопка `variant="default"` «Настроить с афиной» →
`dispatch(start_campaign_flow)` (тот же опрос, что и с welcome). Композиция —
асимметрично-левая, тёплая тьма, жёлтый только на кнопке (60-30-10).

### `page.tsx` (роутинг #11)
Ветка `settingsSurvey` (первый вход в «Настройки», `surveyStatus !== "completed"`)
сейчас монтирует `SurveySection` фуллскрином. Меняем: показывать `SettingsEmptyState`
(не фуллскрин — обычный раздел, нижний бар виден). Кнопка заглушки запускает опрос
через `start_campaign_flow` (переводит `view.kind` в `survey`; по завершении
`surveyStatus → completed` → перерисовка покажет заполненные `SettingsSection`).
`isFullscreen` для этого случая больше не включаем.

## Новые данные

- `src/data/ru-regions.ts` — список регионов/крупных городов РФ (справочник) + пресеты
  (напр. «Города-миллионники РФ»). Формат `{ id, label }[]`. Источник справочника #9.
- Хелпер известных доменов для #10 — плоский dedup-отсортированный список из
  `TRIGGER_DOMAINS` (значения всех триггеров). Разместить как `knownTriggerDomains()`
  рядом с `trigger-domains.ts` или в утиле. Подсказки, `allowCustom: true`.
- Интересы (#6) — из каталога `getInterestById` (`triggers-by-vertical.ts`) +
  `INTERESTS_BY_DIRECTION`. Новый data-файл не нужен.
