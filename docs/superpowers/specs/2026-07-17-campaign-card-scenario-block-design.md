## Цель

Превратить блок «Как работает кампания» в **«Сценарий кампании»**, где детерминированное текстовое описание дополнено **нодо-блоками** с прямой правкой артефактов (база, шаблоны, интересы/триггеры), а блок «Запуск» несёт прогноз касаний и платежи с переходом на оплату. Правка артефактов — прямое детерминированное действие без ИИ. Правка **логики** — предмет спеки 2; пока эта спека убирает старую текстовую воронку правки с карточки (граф остаётся редактируемым через клик в мини-превью → workflow-view).

## TO BE

### 1. Блок «Сценарий кампании» (A2.1)

Заголовок `CardSection` «Как работает кампания» → **«Сценарий кампании»**.

Внутри: детерминированный текст `describeWorkflow` (как сейчас) + под каждым этапом, где есть привязанные артефакты, — **нодо-блок**, визуально совпадающий с нодой воркфлоу (цвет/стиль по `nodeType`).

- **Этап «Старт»**:
  - Источник `new`/`stream` → нодо-блок **`scoring`** с двумя строками:
    - **База** — список файлов + «Добавить файл»; переиспользуем контрол из `node-card-content.tsx:173-271`. Пишет в `Campaign.files` (durable на сессию) и в `ScoringParams.files` кэшированного графа.
    - **Интересы и триггеры** — свёрнутая сводка (счётчик/превью) + раскрытие в **боковую панель** (`InterestsTriggersEditor`, тот же, что в скоринг-дровере). Домены — предмет трека 2.
  - Источник `own` → вместо скоринга нодо-блок **`signal`** с файлом (`SignalParams.fileName`/`files`), без интересов/триггеров.
- **Этап «Первое касание»** → нодо-блоки коммуникаций (`sms/email/push/ivr`), каждый несёт свой шаблон. Выбор шаблона — отдельной спекой (не здесь); здесь блок показывает текущий шаблон и открывает существующий редактор шаблона.

**Правка артефактов — детерминированная, в блоке/панели, без ИИ, без дровера-воронки, мгновенно.** Доступна только до запуска. После запуска блоки read-only (как скоринг-дровер сейчас у запущенной кампании).

Кнопка «Изменить» с локальным текстовым полем и `canEdit`-флоу с карточки **снимается** (сам модуль `useCampaignEditFlow` удаляет спека 2). Мини-превью «Граф кампании» и клик по нему в полный граф — **остаются**: это единственный путь правки логики между этой спекой и спекой 2.

### 2. Блок «Запуск»: прогноз → платежи → «К оплате» (A2.3)

У незапущенных кампаний (`draft`/`paused` — CTA-ветка `campaign-screen.tsx:248`) блок «Запуск» показывает по порядку:
1. **Прогноз касаний** — `estimateTouches(рекомендуемая_сумма, аудитория)`.
2. **Платежи** — `BudgetBreakdown` на `splitCampaignPayments` + `computeCampaignCost`, на рекомендуемой сумме. **То же число, что на экране оплаты** (общие модули). Пересчёт при смене базы/шаблонов — стоимость производна от графа/аудитории, поэтому пересчитывается на ре-рендере карточки (читает `launchGraph`/`campaign`).
3. Кнопка **«К оплате»** → `dispatch({ type:"open_campaign_payment", campaignId })` (существующий action, тот же, что `launch()` сейчас).

Экран оплаты **не меняется**: «Платежи», «Рекомендуемая/Своя сумма», пополнение; его кнопка остаётся **«Запустить»**/«Пополнить и запустить».

Для `paused` сохраняется текущая семантика «Возобновить» (кнопка запуска активирует кампанию без оплаты, `launch()` ветка `status==="paused"`), прогноз/платежи показываем только для `draft`.

### 3. Навигация карточка ↔ граф ↔ оплата (A2.4)

- В **workflow-view** (шапка, у названия кампании) добавить кнопку **«Назад»** → навигация на карточку кампании (обратная к `openWorkflow`; открыть `view.kind==="campaign"` для того же id). Сейчас такой кнопки нет.
- Экран оплаты «Назад» → граф — уже так (`handleBack`), не трогаем.
- Итоговая цепочка: карточка → («К оплате») → оплата → назад → граф → назад → карточка.

### 4. Смещение промпт-бара при боковом дровере (A2.5) + фикс существующего бага

Ввести **единый refcount-стейт ширины активного правого дровера** взамен трёх несогласованных публикаторов `--email-preview-width`:
- Хук `useReserveRightRail(widthPx)` (или контекст): монтируется в дровере, при mount добавляет свою ширину в общий реестр, при unmount убирает; публикует **максимум** активных ширин в CSS-переменную (переиспользуем `--email-preview-width` или новую `--right-rail-width`).
- Перевести на него `scoring-drawer`, `email-editor-panel`, `template-preview-drawer` (снять их индивидуальные `useLayoutEffect`).
- Промпт-бар: правая граница = `var(--right-rail-width, 0px)` вместо хардкода `right-0`; внутренний `max-w-[720px]` **пере-центрируется** в оставшейся видимой области (viewport − sidebar 120px − rail).
- Исключение: собственное нижнее наполнение бара (очередь черновиков, transient-ответ) смещения не вызывает — это не дровер.

Побочно чинит last-writer-wins баг (`chat-drawer` больше не «проваливается» под второй дровер).

## Модель данных

Изменения минимальны — durable-состояние базы уже есть (`Campaign.files`, `ScoringParams.files`). Персист интересов/триггеров и доменов — трек 2 (`Campaign.triggerConfig`). Эта спека их не вводит, только **читает** существующие поля.

## Критерии приёмки

1. Заголовок блока — «Сценарий кампании». Кнопки «Изменить» с текстовым полем на карточке нет. Мини-превью графа и клик в полный граф работают.
2. Под «Стартом» (`new`/`stream`) — нодо-блок скоринга (цвет ноды): строка «База» с файлами и «Добавить файл» (пишет в `Campaign.files`), строка «Интересы и триггеры» с раскрытием в боковую панель. Для `own` — нодо-блок `signal` с файлом.
3. Под «Первым касанием» — нодо-блоки коммуникаций с текущими шаблонами.
4. Правка артефактов — прямо в блоках/панели, без ИИ/дровера-воронки, только до запуска; после запуска read-only.
5. Блок «Запуск» (только `draft`): прогноз касаний → платежи → «К оплате». Число платежей совпадает с экраном оплаты. Пересчитывается при смене базы/шаблонов.
6. В workflow-view есть «Назад» → карточка. С оплаты «Назад» → граф (регресс не сломан).
7. Любой правый боковой дровер (скоринг / панель интересов / чат-дровер / редактор шаблона) сжимает промпт-бар: бар не перекрыт и пере-центрирован в видимой области. Два дровера подряд не ломают ширину (регресс `--email-preview-width` устранён).
