## Согласованные модельные решения

### Модель шаблонов (затрагивает правки 9, 10, 11, 14, 15)

В коде сейчас **два несвязанных источника данных**:
- `PRESET_TEMPLATES` (`src/state/app-state.ts`, seed из `src/state/email-directory.ts`) — питает карточки `TemplateCard`.
- `FIELD_PRESETS` (`src/state/field-directory.ts`) — питает комбобокс полей в нодах `NodeFieldCombobox`.

Они пересекаются только типом `Channel` и `CHANNEL_LABEL`. «Шаблоны должны сходиться с артефактами» = свести ноды и карточки к **одному** источнику.

**Финальная модель (упрощённая, согласована):**
- **Шаблон** = именованный набор компонентов (заголовок, текст, отправитель и т.д.), привязанный к типу канала ноды. Без авто-композиции из атомарных сущностей — это явный именованный объект.
- В коммуникационной ноде свободные поля **Текст/Заголовок убираются**; вместо них — **селект шаблонов**: простой select, показывает название шаблона, отфильтрован по каналу ноды.
- У каждого пункта селекта справа — **кнопка предпросмотра**, которая открывает дровер с расписанными составляющими шаблона (ИИ пишет заголовок/текст/отправитель/…), **не закрывая селект**.
- В селекте есть пункт **«создать новый шаблон»** → открывает дровер создания (тот же поток, что в разделе Артефакты).
- Создать шаблон можно из раздела **Артефакты** ИЛИ прямо **из графа** через селект.
- Название шаблона можно **переименовать** в разделе Артефакты.
- Ноды и карточки питаются из **одного источника** (`templates` в app-state) — это и есть «сходимость» (правка 9).

### Поток создания шаблона = в чат-дровере (правки 14, 15)

Модалка («мочалка») `TemplateDrawerView` убирается. Создание/предпросмотр шаблона происходит в **существующем боковом чат-дровере** (`ChatDrawer`):
- Каждый вопрос ИИ — **отдельное сообщение ассистента** в `ChatHistoryList`.
- Варианты ответа — в **пикере над промпт-баром** (см. референс пользователя, Image 1):
  - Заголовок пикера = текст вопроса, справа × для закрытия.
  - Пронумерованные варианты (1, 2, 3…), навигация ↑↓, выбор по Enter / цифре; у активного пункта — иконка ⏎ справа.
  - Строка свободного ввода **«Другой вариант»** (иконка-карандаш) + кнопка **«Пропустить»** справа — **опциональны**: показываются только когда вопрос допускает свободный ответ. Для **детерминированных/закрытых** множеств (например, выбор типа канала) этой строки нет — только фиксированные варианты.
  - Снизу композер с русским плейсхолдером (напр. «Или напишите ответ…») и хинт-строка `↑↓ — навигация · Enter — выбрать · или впишите ниже`.
  - **Все подписи и плейсхолдеры — только на русском.** Никаких английских строк (в референсе они английские лишь как пример).
- На шаге выбора варианта (правка 15) в пунктах показываем **состав компонентов** шаблона (какой набор текстовых компонентов предлагается), не только название.

### Корректность AI-правок графа (правка 16)

Референс пользователя (Image 2, жёлтые рамки = добавлено ИИ) подтверждает два дефекта:
1. **Терминальная нода в середине потока** — «Конец 2» вставлена между СМС и Условием, а не в конец ветки.
2. **Split не ветвится** — `applyReplace` (`src/state/structural-commands.ts:639`) при замене ноды сохраняет старые рёбра (`edges: graph.edges`, строка 681), поэтому новый сплиттер наследует один вход/один выход → плоская структура вместо разветвления на сегменты с разными каналами.

## Стратегия параллелизации и швы

- **Льются параллельно сразу:** блоки 1, 2, 3, 4 — пересечений по файлам нет.
- **Блок 5 ↔ блок 6:** селект блока 5 («создать»/«предпросмотр») вызывает дровер блока 6. Сначала фиксируем **контракт дровера** (как открыть создание / как открыть предпросмотр шаблона по id, не закрывая вызывающий UI) — тогда 5 и 6 идут параллельно, стыкуются по интерфейсу.
- **Блок 5 ↔ блок 7:** оба правят `src/lib/ai/orchestrator-prompt.ts` (блок 5 — убирает node-params правку текста, блок 7 — чинит ops ветвления). Развести: либо последовательно, либо один владелец файла, второй отдаёт diff.
- **Блок 2 ↔ блок 5:** оба касаются `app-state.templates` (блок 2 — rename action, блок 5 — единый источник для нод). Согласовать форму `MessageTemplate` заранее (общий мини-контракт типа), дальше независимо.
- **Риск-ранжирование:** блок 7 (движок `structural-commands.ts`, ~875 строк) и блок 5 — самые глубокие/рискованные. Блоки 1–4 — низкий риск, мелкие правки.

### Порядок запуска
1. Зафиксировать общие контракты: форма `MessageTemplate`, API дровера (создание + предпросмотр), владение `orchestrator-prompt.ts`.
2. Параллельно: 1, 2, 3, 4 (сразу) + 6 (дровер) + 7 (граф).
3. Блок 5 стартует, когда готов контракт дровера блока 6 (или одновременно, по интерфейсу-заглушке).
