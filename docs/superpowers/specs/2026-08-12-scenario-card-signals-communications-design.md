# Карточка сценария: этапность «Сигналы / Коммуникации», инлайн-теги, Итог

Дата: 2026-08-12 · Ветка: `claude/scenario-card-signals-communications-889ee8`

## Контекст

Блок «Сценарий кампании» на карточке кампании рендерит детерминированное текстовое
описание графа (`describeWorkflow` → `WorkflowDescription`). Сейчас:

- Заголовки блоков — «Сигнал (Скоринг)» и «Коммуникации», без нумерации.
- База и Триггеры показаны отдельным списком `<dl>` «подпись — значение» под прозой
  (две строки, занимают много места).
- Коммуникации рендерятся стопкой строк «канал (жирный) · тег-шаблон · 👁 предпросмотр»,
  плюс пилюля «N каналов» во вводной.
- Блок «Итог» (черновик) несёт подводку «За что платите: …» и `BudgetBreakdown`,
  свёрнутый по умолчанию; пояснение про Первичные/Повторные — абзацем внутри
  раскрытой таблицы.
- При открытии правого дропера съезжает только промпт-бар (`--right-rail-width`),
  контент карточки остаётся под дропером.

Формы графа (важно для текста) задаются `signalType × sourceType × channels`:

- **A. Линейная + повтор** — new/stream, обычные типы, ≥1 канал.
- **B. Сегментный форк** — new/stream, Апсейл/Удержание (`SEGMENTED_TYPES`), ≥1 канал:
  split по сегменту склонности → ◈-ветки.
- **C. Без коммуникаций** — `channels: []` → блок 2 отсутствует.
- **D. Своя база (own)** — нет ноды скоринга (`hasScoring=false`).
- **E. Один канал** — «Каждому контакту…» вместо «делится по каналам».

## Изменения

### 1. Нумерация заголовков блоков
- `BLOCK_LABEL.signal`: «Сигнал (Скоринг)» → «Сигналы».
- Рендер префиксом: «1. Сигналы», «2. Коммуникации» (фикс: signal=1, communication=2).

### 2. Сигнальный текст — инлайн-теги База/Триггеры
Убрать `settings`-`<dl>` для базы и триггеров; вплести в прозу тегами.

Скоринговый кейс:
> Загруженная база **[N строк]** проходит скоринг. Дальше — скоринг по **[триггерам]**:
> остаются те, кто проявляет намерение, с разбивкой по уровням склонности.

- Множ. число базы — по числу файлов (`campaign.files.length`): «Загруженные базы …
  проходят …». Счётчик строк — суммарный (`baseRows`).
- Нет триггеров → клауза про триггеры опускается.
- Фраза модерации доменов по-прежнему добавляется в конце.
- Не-скоринговый кейс (D) — прежняя формулировка «попадает в кампанию…», но с
  инлайн-тегом базы; тега триггеров нет.

Теги:
- **База** — существующий `BaseFilesTagPopover` (label «N строк»). Без изменений.
- **Триггеры** — новый тег-цель `{ kind: "triggers" }`, label «триггерам»,
  `hoverList` = список триггеров. Клик поднимается через `onActivate`:
  - **только в черновике** (`graphEditable`) и **только при наличии ноды скоринга**;
  - действие: `openScoringDrawer({ nodeId: scoringNodeId, campaignId, editable })`
    + `pushScoringContext("Триггеры")` (чип контекста в промпт-бар);
  - в запущенной кампании тег — обычный носитель значения без клика.
- Тег строится только при `hasScoring && hasTriggers` (иначе D/пустые — без тега).

### 3. Коммуникации — инлайн-текст
- Убрать пилюлю «N каналов» (`channelsIntro` с тегом).
- Строки касания рендерятся **инлайн в предложении**, а не стопкой; кнопка 👁 убрана.
- Названия каналов — обычный текст, строчными в потоке (`channelProseLabel`:
  строчная первая буква, кроме аббревиатур типа SMS). Шаблоны — пилюли-теги.

Формулировки:
- Первое касание (много каналов): «Аудитория делится по каналам, каждому приходит своё
  сообщение: SMS с шаблоном **[тег]** и звонок с шаблоном **[тег]**.»
- Один канал (E): «Каждому контакту уходит первое сообщение: SMS с шаблоном **[тег]**.»
- Повтор: «Та же серия по тем же каналам: SMS с шаблоном **[тег]** и звонок с шаблоном
  **[тег]**.»
- Форк (B): «…делится на N потоков по **[уровню склонности]**, каждый получает своё:»,
  далее по ветке «◈ Высокая склонность: SMS с шаблоном **[тег]** и звонок…».

Реализация: инлайн-склейка каналов строится хелпером над `group.rows`
(`{канал} с шаблоном [тег]`, разделители «, » / « и »). Для **не-форк** волн склейка
вплетается в `stage.body`, `groups` не выпускаются. Для **форк** волн `groups` остаются
(с `label`), их строки рендерятся инлайн после ◈-подписи. `withTags=false` → только
имена каналов без пилюль.

Мёртвый код удаляется: `PreviewButton`, `rowDistinctions`, `contentSnippet`,
`ambiguousHeadings`, `ROW_LABEL_LIMIT` (обслуживали только 👁).

### 4. Итог (черновик)
- Подводка:
  > **Вы платите за скоринг базы и коммуникации.**
  > Деньги списываются с вашего счёта во время запуска кампании.
- `BudgetBreakdown` в этом блоке — `defaultExpanded` (раскрыт).
- Абзац Первичные/Повторные убрать; содержание — в тултипы заголовков колонок:
  - *Первичные*: «Первое касание — покажем каждому получателю.»
  - *Повторные*: «Дополнительное касание — тем, кто не отреагировал. Обычно повышает
    отклик; можно отключить при настройке.»
- `defaultExpanded` меняется только в блоке «Итог» карточки (визард/экран оплаты — как
  были). Тултипы — изменение общего `BudgetBreakdown` (везде одинаково).

### 5. Сдвиг контента при открытии дропера
- `EntityCardShell` (скролл-контейнер) получает `padding-right: var(--right-rail-width, 0px)`
  — весь контент карточки съезжает и рецентрируется (прецедент — `campaign-workspace`).
  Область — правый рельс (дроверы скоринга/предпросмотра). ИИ-дровер
  (`--chat-sidebar-width`) — вне scope этой правки.
