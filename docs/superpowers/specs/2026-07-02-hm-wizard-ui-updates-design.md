# HM Wizard — пакет UI-правок

**Дата:** 2026-07-02
**Ветка:** `claude/hm-wizard-ui-updates-cusfnu`
**Тип:** пакет независимых UI-правок (визард создания кампании, экран артефакта, ноды workflow, карточки кампании)

## Контекст

Пакет из семи независимых правок по итогам ревью прототипа. Каждая правка локальна и не зависит от остальных; их можно реализовывать и ревьюить по отдельности. Термины: «кампания» = campaign; «разовая/потоковая» = каденс кампании (once/stream); «выжимка» = дневной артефакт потока (`Artifact.variant === "daily"`).

Источник истины каденса: `Campaign.sourceType` (derived из `intent` + `analysisMode` через `deriveSourceType`). `stream` → потоковая; `new` / `own` → разовая; `undefined` → не определено.

## Правка 1 — Кнопка «Назад» на каждом экране визарда

**Файлы:** `src/sections/campaigns/wizard/steps/step-2-interests.tsx`

**Текущее состояние.** `StepFooter` рендерит «Назад» при наличии пропа `onBack`; `campaign-workspace.tsx` уже прокидывает `onBack = () => handleGoToStep(step - 1)` (плавный скролл к предыдущему шагу) во все шаги. Все шаги, кроме одного, уже пробрасывают `onBack` в `StepFooter` (intent, analysis, file, integration, channels, budget). **Единственный пробел** — `Step2Interests`: он деструктурирует `{ data, onNext, active }` без `onBack` и не передаёт его в `StepFooter`, поэтому на экране «Интересы» кнопки «Назад» нет.

**Правка.** Принять `onBack` в сигнатуре `Step2Interests` и передать в `StepFooter`. Первый экран (сценарий) остаётся без «Назад» — у него нет футера и нет предыдущего экрана (подтверждено пользователем: «Только со 2-го экрана»).

**Проверка.** Существующий `tests/e2e/wizard-buttons.spec.ts` проверяет правое выравнивание primary CTA; добавить проверку присутствия кнопки «Назад» на шаге «Интересы».

## Правка 3 — Дневные выжимки: скрытие при >5 + «Показать все (N)»

**Файлы:**
- `src/sections/artifacts/artifact-screen.tsx` (секция «Дневные выжимки» — Скрин 1)
- `src/sections/campaigns/campaign-artifacts-block.tsx` (компактный блок раскрытой карточки — Скрин 2)

Пользователь подтвердил: **оба места**.

**Поведение (оба места).**
- Если дневных выжимок ≤ 5 — показывать все, без кнопки.
- Если > 5 — по умолчанию показывать первые 5 (самые свежие), ниже кнопка-тоггл **«Показать все (N)»**, где `N` — **общее** число выжимок (по примеру пользователя: было 10, показано 5 → кнопка «Показать все (10)»).
- В развёрнутом состоянии кнопка — **«Свернуть»**.
- Раскрытие/сворачивание анимируется тем же `ease-out-quart` (`[0.23, 1, 0.32, 1]`, ~0.28s), что и `collapseMotion` в `step-1-scenario.tsx` (PRODUCT.md §анимация). Анимируем opacity/height блока дополнительных строк.

**Скрин 1 (`artifact-screen.tsx`).** Секция `Дневные выжимки` сейчас рендерит `dailies.map(...)` целиком. Ввести локальный `useState` `expanded`; срез `expanded ? dailies : dailies.slice(0, 5)`; кнопка-тоггл под списком, если `dailies.length > 5`.

**Скрин 2 (`campaign-artifacts-block.tsx`).** Сейчас показывает cumulative-строку + `dailies.slice(0, 3)` + статичный текст `…ещё N выжимок`. Правка: порог 3 → 5; заменить статичный `…ещё N` на кликабельный тоггл **«Показать все (N)»** (N = общее число выжимок) / **«Свернуть»** с локальным `expanded`-состоянием. Тоггл разворачивает список **inline** (не переходит на экран артефакта — навигация остаётся только на строках выжимок через `onOpen`). `stopPropagation` на кнопке, чтобы не триггерить строку.

**Проверка.** Юнит-тесты `campaign-artifacts-block.test.tsx` и `artifact-screen.test.tsx`: ≤5 без кнопки; >5 показывает 5 и кнопку с общим N; клик разворачивает все и меняет надпись на «Свернуть».

## Правка 4 — Динамический статус артефакта + убрать «Об артефакте»

**Файлы:** `src/sections/artifacts/artifact-screen.tsx`

**Текущее состояние.**
- В `meta` шапки: зелёная галочка + «Артефакт собран · {дата}».
- Секция «Об артефакте» (Тип файла / Кампания / Тип / Создан).
- `secondaryActions`: «Скачать общий» + «Удалить».

**Правки.**
1. **Динамический статус** в `meta`. Определяется по `campaign.status`:
   - активная кампания (`status === "active"`) → **«Артефакт собирается, обновляется каждый день в 00:00»** (иконка «в процессе», не зелёная галочка «готово»);
   - завершённая (и все прочие терминальные) → **«Артефакт собран · {дата}»** (как сейчас).
   - Разовый артефакт (не `cumulative`): по той же логике статуса кампании; на практике почти всегда «собран».
2. **Убрать секцию «Об артефакте»** полностью (`<CardSection label="Об артефакте">…</CardSection>` и хелпер `SummaryRow`, если он больше нигде не нужен; секция «Настройки кампании-источника» остаётся).
3. **Кнопки** «Скачать общий» / «Удалить» — без изменений.

**Проверка.** `artifact-screen.test.tsx`: активная кампания → строка «собирается…»; завершённая → «собран»; секция «Об артефакте» отсутствует; кнопки скачивания/удаления на месте.

## Правка 5 — Обязательный шаблон в ноде блокирует запуск

**Файлы:** `src/sections/campaigns/campaign-screen.tsx`, `src/sections/campaigns/campaign-launch-gate.ts` (или вызов `validateWorkflow` в месте гейта)

**Текущее состояние.** `nodeNeedsAttention` уже флагит незаполненную коммуникационную ноду (sms — пустой `text`; email — `subject/body/sender`; push — `title/body`; ivr — `scenario`) → нода красится жёлтым кругом (`workflow-node.tsx`, `data.needsAttention`). Но кнопка «Запустить» гейтится только `canLaunchCampaign(campaign)`, которая смотрит лишь `status`/`sourceType`/`phase` и **не учитывает** валидацию графа. Поэтому запуск возможен при незаполненном шаблоне.

**Правка.** Гейтить запуск дополнительно на `validateWorkflow(graph, signalBound).ok`. Пользователь подтвердил: **любая** нода `needs-attention` (и прочие ошибки валидатора — нет сигнала, нет success-пути) блокирует запуск. Кнопка «Запустить» в состоянии disabled, когда граф невалиден; жёлтый круг на нодах (уже есть) указывает, что настраивать.

**Реализация.** В `campaign-screen.tsx` рядом с `canLaunch = canLaunchCampaign(campaign)` вычислить валидность графа кампании и объединить: `canLaunch && workflowValid`. Граф и `signalBound` брать из того же источника, что `workflow-section.tsx` (там уже есть `validateWorkflow(g, true)` — переиспользовать логику/селектор). Если у ноды пустой шаблон и это не отражается в `needsAttention` для каких-то каналов — свериться с `nodeNeedsAttention` и покрыть тестом.

**Проверка.** Тест: кампания-черновик с нодой без шаблона → `canLaunch`-комбинация `false` (кнопка disabled); после выбора шаблона → `true`.

## Правка 7 — Разовая/потоковая на карточках кампании

**Файлы:** `src/sections/campaigns/campaign-card.tsx` (список), `src/sections/campaigns/campaign-screen.tsx` (раскрытая карточка); общий хелпер каденса — новый или рядом с `campaign-metrics`.

**Уточнение пользователя.** Тип источника («Поток» / «Новая база номеров» / «Свои сигналы») больше не показываем — работаем через интент. Показываем только **«Разовая»** / **«Потоковая»**.

**Хелпер.** `campaignCadenceLabel(sourceType?: SourceType): "Разовая" | "Потоковая" | null`
- `"stream"` → `"Потоковая"`
- `"new" | "own"` → `"Разовая"`
- `undefined` → `null` (чип не показываем — «если применимо»)

**Список (`campaign-card.tsx`).** Убрать текущий чип `sourceLabel` (SOURCE_LABEL). Вместо него — чип каденса из хелпера (тот же стиль бордер-чипа). Чип «Сценарий: …» остаётся. Если каденс `null` — второго чипа нет.

**Раскрытая карточка (`campaign-screen.tsx`).** В `tags` рядом с `<CardTag>Сценарий: {scenarioName}</CardTag>` добавить `<CardTag>{cadenceLabel}</CardTag>` при `cadenceLabel !== null`. (Источник в раскрытой карточке как отдельный чип сейчас не показывается — только «Сценарий», — так что это чистое добавление.)

**Проверка.** `campaign-card` (юнит): stream → «Потоковая»; new/own → «Разовая»; без sourceType → нет чипа каденса, старый source-чип отсутствует. Обновить визуальные бейзлайны (`campaign-card`, `section-campaigns`) — Правка 7 меняет чипы.

## Общие замечания по реализации

- **Визуальные снапшоты.** Правки 3, 4, 6, 7 меняют вёрстку соответствующих экранов — потребуется обновление Playwright-бейзлайнов (`tests/e2e/screens.visual.spec.ts-snapshots/`). Скриншоты снимаются с `executablePath: /opt/pw-browsers/chromium-1194/chrome-linux/chrome` (в окружении версия браузера расходится с pinned playwright).
- **Каденс-хелпер** переиспользуется списком и раскрытой карточкой — вынести в один модуль, не дублировать маппинг.
- Каждая правка — отдельный маленький коммит; порядок не важен (правки независимы).

## Вне scope

- Смена самой модели `sourceType` → `intent`/`analysisMode` на `Campaign` (правка 7 работает поверх существующего derived `sourceType`).
- Логика самого стрим-таймера/сбора артефактов (правка 4 меняет только отображение статуса).
- Редизайн нод/футеров сверх перечисленного.
