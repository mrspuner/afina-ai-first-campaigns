## Решения по расхождениям (Часть 2 исходного документа)

| # | Расхождение | Решение |
|---|---|---|
| Р1 | Цвет тега-параметра | **Внедряем.** Фон `#4C4C4E`, белая обводка, белый жирный текст. |
| Р2 | «База» и «Триггеры» не видны | **Кода не касается.** `start-base` и `start-triggers` выводятся (`graph-description.ts:509,531`), гейтятся наличием факта. На скриншоте их нет, потому что у демо-кампании не заданы файлы базы и триггеры — это данные сида. |
| Р3 | Цвета тегов-шаблонов | **Внедряем через `NODE_STYLES`.** Перекрашивается и граф на канвасе — это требование спеки («тот же токен, рассинхрон недопустим»). Побочно чинит нарушение `PRODUCT.md`: текущий email-циан `#67e8f9` — прямой анти-референс «cyan-on-dark». |
| Р4 | «Предпросмотр» — не кнопка | **Внедряем как кнопку-иконку** (решение пользователя): квадратная кнопка с глазом, колонка ~52px. Спека §1.7 просила иконку с подписью, прототип — только иконку; выбран прототип. Подпись живёт в `aria-label` и тултипе. |
| Р5 | «Аудитория делится по каналам» | **НЕ внедряем** (решение пользователя). Формулировка оставлена как есть: слово «поток» закреплено за сегментами аудитории. Возврат к «потокам» дал бы одно слово в двух значениях внутри одного описания — шаг 2 (канал) и шаг 3 (сегмент). |
| Р6 | Нумерация без бейджей | **Внедряем.** Кружок-бейдж + вертикальная линия-таймлайн. |
| Р7 | Таблица без панели | **Внедряем.** Обрамлённая панель. |
| Р8 | Push: заголовок + текст | **Оставляем заголовок + текст** (решение пользователя, подтверждает прежнее). Прототип показывает только текст — не следуем ему здесь. |
| Р9 | Иконка блока | **Оставляем как есть.** Жёлтая иконка — кнопка «Изменить логику кампании с ИИ»; жёлтый там санкционирован `PRODUCT.md` (маскот / AI-индикация — разрешённое место акцента). |

### 1. Тег-параметр (`description-tag.tsx`)

Сценарий, База, Триггеры, Режим, Бюджет, Каналы.

| Свойство | Значение |
|---|---|
| Фон | `#4C4C4E` |
| Обводка | 1px `#FFFFFF` |
| Текст и иконка | `#FFFFFF`, вес 600 |
| Радиус | 7px |
| Паддинг | ~1–2px по вертикали, 7px по горизонтали |
| Hover (черновик) | фон `#8B8B8D`, обводка белая, `cursor: pointer` |
| Запущенная кампания | **тот же вид**, без клика и без hover-подсветки |

Это заменяет нынешний `NEUTRAL_CLASS` (`bg-foreground text-background`). Правило «демоция снимает интерактив, а не цвет» сохраняется — оно и здесь то же самое.

### 2. Клик по тегу-параметру → поповер с «Изменить»

Сейчас клик уводит на шаг визарда напрямую. Становится:

1. Клик по тегу раскрывает **поповер над тегом**: подпись «Настройка · <название>» и кнопка **«Изменить»**.
2. Кнопка «Изменить» диспатчит существующий `campaign_step_edit_requested` — тот же переход, что и сейчас, просто за одно нажатие дальше.
3. У запущенной кампании (цель `none`) поповер не открывается вовсе.

Тултип «Нажмите для изменения» на теге-параметре снимается — его роль берёт поповер.

### 3. Тег-шаблон и цвета узлов (`node-visuals.ts`)

`NODE_STYLES` — единственный источник цвета и для узла графа, и для тега. Перекрашиваем коммуникационные каналы (значения из прототипа):

| Канал | border | bg | color |
|---|---|---|---|
| `sms` | `#2f6b4d` | `#12241b` | `#8ff0c4` |
| `push` | `#2f5580` | `#111d2b` | `#a9caff` |
| `email` | `#523a78` | `#1b1327` | `#d6bcff` |
| `ivr` | `#7a5730` | `#271a10` | `#ffcf9e` |

Логические узлы:

| Узел | border | bg | color |
|---|---|---|---|
| `wait` | `#4a3c1c` | `#2a2314` | `#f2b34a` |
| `condition` | `#5a2f52` | `#241020` | `#e08bd0` |
| `split` | `#5a2f52` | `#241020` | `#e08bd0` |

Легаси-узел `channel` дублирует палитру `sms` — двигается вместе с ним.

**Проверить и починить, если разъехалось:** мини-превью графа и полный канвас читают те же `NODE_STYLES`; после правки они обязаны показывать те же цвета, что теги описания.

### 4. Теги паузы, условия и деления

- **Пауза** — уже цель `node-fields` с поповером `WaitFields`. Цвет приходит из `NODE_STYLES.wait` (см. выше), отдельной раскраски не заводим.
- **Условие** (`condition`) — становится **кликабельным** тегом с поповером: `NodeFieldCombobox` над полем «Событие» (`optionsKey: "eventCatalog"`, `paramKey: "trigger"`), без `onAiHandoff` — на карточке ИИ-дровера полей нет, и отсутствие колбэка само гасит пункт «Сформировать с помощью ИИ». Цвет — `NODE_STYLES.condition`.
- **Деление** (`split`) — остаётся **некликабельным** тегом. Поля сплиттера правятся только через ИИ (`NODE_FIELD_EDITABILITY.split` → `editability: "ai"`), а ИИ-дровер полей на карточке отсутствует. Кликабельный тег без работающего редактора был бы мёртвой кнопкой. Цвет — `NODE_STYLES.split`.

У запущенной кампании оба тега демотируются в `none`: цвет остаётся, клик пропадает.

### 5. Шаг: бейдж и таймлайн (`workflow-description.tsx`)

### 6. Таблица коммуникаций

- Разделители строк — `#212127`; у последней строки разделителя нет.
- Заголовки столбцов — 10px, uppercase, `#6D6E78`, вес 500.
- Ширины `<colgroup>` (одинаковые у всех таблиц шага): Коммуникация `110px`, Шаблон `196px`, Контент — авто, Предпросмотр `52px`.

## Токены

Значения выше — из макета. Правило: где значение совпадает с существующим токеном `src/app/globals.css`, использовать токен; где нет — **добавить токен в `globals.css`**, а не разносить хекс по компонентам. Исключение — `NODE_STYLES`: это уже реестр сырых хексов и единственный источник цвета узлов, там значения живут как есть.

Жёлтый `#FFEC00` в этой работе не применяется. Янтарь паузы `#f2b34a` — не брендовый жёлтый и приходит из палитры узла, а не из акцента.

## Критерии приёмки

1. Тег-параметр: фон `#4C4C4E`, белая обводка, белый жирный текст; у запущенной кампании вид тот же, клика нет.
2. Клик по тегу-параметру в черновике раскрывает поповер с кнопкой «Изменить»; переход на шаг визарда происходит по кнопке, а не по клику на тег.
3. Теги шаблонов различаются по каналам и совпадают по цвету с узлами графа: SMS зелёный, Push синий, Email фиолетовый, Звонок оранжевый.
4. Мини-превью графа и полный канвас показывают те же цвета, что теги описания.
5. Тег условия кликабелен и раскрывает поповер выбора события; тег деления некликабелен.
6. Номера шагов — в кружках-бейджах, соединённых вертикальной линией.
7. Таблица коммуникаций — в обрамлённой панели с разделителями строк; шапка один раз на шаг.
8. Кнопка предпросмотра — квадратная кнопка-иконка; подпись доступна скринридеру и в тултипе.
9. Формулировка «Аудитория делится по каналам» и контент Push «заголовок + текст» — **не менялись**.
10. `npx vitest run` — 0 красных; `npx tsc --noEmit` — те же 13 предсуществующих; `npm run lint` — без новых; визуальные базлайны обновлены осознанно.
